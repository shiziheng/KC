## 六、关键决策（已定，不可违背）

1. **注入式改版，不重建前端、不动 Xboard 内核**（项目红线）。
2. **配置驱动**：价格/文案/品牌一律走 `site-config`，代码零硬编码；"省 $X/净赚 $Y"由前端按数字**自动算**。
3. **价格前置转化顺序**（用户拍板）：先给价格 → 再给门槛对比（$15 vs 数千美元）→ 最后解释权益包机制。
4. **压制而非删除**：旧版内容隐藏不删，随时回退。
5. **配色**：品牌强调色 = 省钱绿 `#00A862`（demo A 方案墨黑+绿）；价格/省钱文案用已有的 `--kc-green:#16a34a` 单独强化，避免稀释。
6. **命名红线**：禁"会员/等级/升级/VIP"；统一句式「用 1 次权益，省 $10」。
7. **按月付费，无年付**（代充行业惯例）。
8. **品牌名 KC 直供**（已定）；「菲区」商品名保留（代充行业特点）。
9. **进度只写本文件**（单一事实源）。
10. **每步必须留「验收测试用例」**：功能测试工程师视角 ≥3 条 + UX 专家视角 ≥3 条，逐条实测；全绿自动进下一步（用户 2026-10-14 要求）。
11. **权益包 ≠ 代充（产品铁律，用户 2026-10-14 拍板）**：代充照旧存在；买权益包**只是让之后的代充更便宜**；**买权益包绝不进入代充流程**（不进开通向导、不粘贴 Session、不发卡）——因此导航**保留**「代充」项，权益包走**独立页 `#/pack`**。

13. **买权益包不得覆写用户订阅**：`OrderService::open()` 对 `kc_card.category='entitlement'` 的商品直接置 `STATUS_COMPLETED` 返回，不改 `v2_user.plan_id/expired_at`（实测铁证见 Step 6）。

3. **admin.html / 商城页有浏览器缓存**：CDP 验证必须禁用缓存 + 强刷，否则看到旧版。
4. **商城是 hash 路由，未知路由重写成 `#/404`**：新页面要用 `pushState` + 意图记忆（见 `kc_wallet_inject` 的钱包页先例）。
5. **Vue 重建 DOM 会冲掉注入**：用"首帧压制 + 就绪式解除 + 定时守护"三件套（现有块都是这么做的）。
6. **`v2_order` 无套餐名快照**：别删有订单引用的商品；删商品前先删其订单。
7. **`show` 是 MySQL 保留字**：SQL 里写 `` `show` ``。
8. **改 DB `custom_html` 后必须回灌本地源**（`_v129_sync_sources_from_db.js --write`），否则下次全量部署静默回滚。
9. **商品接口字段是 `plan_id` 不是 `id`**；`/api/admin/products` 返回 `{success, data}`，`show` 是 boolean。
10. **配色改造前后文件长度可能不变**（不同汉字同字节数）：**判断成功与否看内容，不看长度**。
11. **后台 admin 未登录跳 `/admin-login`**；token 键 `plus_admin_token`；页面机制：菜单 `data-page="X"` ↔ 容器 `<div id="X" class="page-view">`。
12. **压制旧门户别跟主题块抢 specificity**：主题块的压制规则只针对 `section.cus-scroll-y > div`。新门户容器用 **`<section>`** 即可天然豁免；隐藏 `#kc-portal` 只需 `body.kc-home-v2 #kc-portal{display:none!important}`。反之若新容器用 `<div>`，就要打 specificity 仗。
13. **`site-config.plans` 为空时双价退化**（商品卡只显原价、Hero 不出现权益价）——不报错，但看起来"没生效"。先跑 `node tools/_v132_set_plan_price.js --apply` 录价。**`plans[].planId` 对应 Xboard 商品 `plan_id`，不是 `id`。**
14. **装饰性圆点别按次数铺满**：`dots()` 已限制最多 5 个；早期版本按 50 次铺 50 点会横向溢出、撑破权益包三栏网格。
15. **商品卡给主题块预置了数据属性**：`#/plan` 卡片上有 `data-kc-card="1"` / `data-kc-plan-id` / `data-kc-price-fen`（分）/ `data-kc-price-label` / `data-kc-period`（主题块 `applyCardNode` 写入）。**加标注层时直接读卡属性即可拿原价**，不必再查商品接口（接口仅用于「与首页同源」的原价口径）。
16. **压制主题价格行要一并搬运角标**：`.kc-cb-price` 里除 `$15` 还有 `.kc-cb-tag`（如「官方直充」）——直接 `display:none` 会把角标一起藏掉；先在标注层里搬运该角标文案再压制。
17. **`#/plan` 列表 vs `#/plan/<id>` 详情要区分**：双价块用 `h.indexOf('#/plan')===0 && !/^#\/plan\/\d+/.test(h)` 只认列表页；离开商品页必须 `clear()`（移除 `.kcdp-has` 压制类 + 标注层），否则若卡片 DOM 残留、样式失配会露出无样式标注。
18. **顶栏/抽屉首项文案会被 `setupNavCategories()` 回写**：该函数原本 `anchor.textContent = cats[0].name`（写入后台首个分类名「代充」）。Step 4 曾把首项改名「权益包」，Step 6 已回正为「代充」（`data-cat="recharge"`）——**无论首项叫什么，都必须删掉文案回写、只保留 `data-cat` 同步**，否则静态文案会被后台分类名覆盖。同理「权益包」是**硬编码**的新增项（`data-pack="1"`），后台分类配置里没有对应分类，`setupNavCategories` 不得遍历改动它。
19. **导航「项数」验收要按分区数**：抽屉 `.kc-drawer-nav` 内除「导航」区 5 项（代充/成品号/建站服务/权益包/我的订单）外，还有「更多功能」区（个人中心/邀请/工单）＋动作按钮（充值/兑换卡密）。断言需在遇到 `div.kc-drawer-cap`（「更多功能」小标题）时截断，否则会把 8 个 `<a>` 全数进来误判。
20. **`v2_plan.prices` 的单位是「元/美元」，不是「分」**：Xboard 结算时 ×100 落成 `total_amount`（分）。故插件 `fee_cents = prices.onetime × 100` 是对的（`onetime=60` → $60.00）。别按"分"读成 $0.60。
21. **Xboard 结算 = 「旧订单剩余价值折抵优先、余额补差」**：`v2_order.balance_amount + surplus_amount = 应付总额`（实测：权益包 $60 = `balance_amount 468` + `surplus_amount 5532`）。⇒ 「用余额开通」按钮下，**余额扣减额可能远小于包价**；验收断言只能判「余额已减少」，**不可硬编码差额**（如 `$200 → $140`）。
22. **插件路由没有 `/api` 前缀**：分组是 `Route::prefix('kc/order')`，故真实路径是 `POST /kc/order/pay-balance`，**不是** `/user/kc/order/pay-balance`（写错会 404，且 Laravel 报错文案里的路径会误导）。用 `php artisan route:list --path=xxx` 核实。
23. **一次性成功提示会被重绘冲掉**：`renderPack()` 的 `box.innerHTML = html` 会重置页面文案 ⇒ 必须 ①用渲染序号 `packSeq`（并发重绘只认最新一次）②`packFlashMsg` 设为「粘性」（跨重绘保留，离开页面或发起下一次开通才清）；早期「首次重绘后清空」的写法与并发重绘竞态，会把「开通成功」覆盖成静态文案。
24. **`checkKc`「权益包≠代充」页面断言**：`#/pack` 页内**不得**出现「Session / 卡密」等代充兑卡要素 —— 这是产品铁律的机检项，已纳入 `_v133_pack_verify.js`。
25. **`kc_order_pricing_snapshot.applied_rule_id` 是 `bigint unsigned`**（存的是**规则自增 id**，不是规则 `code` 字符串）：写快照时若把 `code` 塞进去会报错并被 `try/catch` 吞掉（表现为「consume 说无报价记录」）。⇒ INSERT 该列传 **null**，把规则 `code` 存进 `snapshot_json.entitlement.rule_code`；`plan_id` 由 `xplan_<id>` 反解。
26. **Xboard 余额足额抵扣时 `total_amount` 归零**：`total_amount=0` 是**正常**的（抵扣额记入 `balance_amount`）。验收断言应付金额必须用 `total_amount + balance_amount + surplus_amount` 之和，**不可**只看 `total_amount`（否则误判为「没扣钱」）。
27. **定价唯一事实源是 `kc_entitlement_prices`（Step 8 起）**：权益价一律按（权益包 × 商品）一口价查表；**未配置 = 按原价**（不做规则级折扣兜底）。规则表 `kc_entitlement_rules` 的 `discount_type/discount_value/plan_scope/min_order_cents` **已降级为元数据、不再参与定价** —— 改规则表单里的折扣**不会**影响任何报价。后台改价去「权益报价」页。
28. **`kc_entitlement_prices` 表初始为空 + 报价量纲是「分」**：表无种子，运营手填，空表时前台**所有人只看到原价**（属正常，不是"没生效"）。`price_cents` 单位是**分**（`$9.00` 填 `900`）；而后台展示的「原价」由 `v2_plan.prices`（**主单位/美元**）经 `entitlementListPriceCents()` 按周期取首个 > 0 价 **×100** 得出 —— 两边单位不同，别混用。
29. **首页门户与 `#/plan` 已同源（Step 8）**：两处都调 `POST /user/kc/quotes`，口径统一为「我方原价」，首页**不再**读 `site-config.plans[].quotaPrice/marketPrice`。⇒ 旧断言（首页 `$12.00`/省 `$8.00`）与 `_v134_settle_verify.js` 的「6 折 `$9.00`」期望值**均已过期**，Step 8 验证以 `tools/_v135_pricing_verify.js` 为准。
30. **`_v133_pack_verify.js` 的 ④「未开通时有空态引导文案」已失效（Step 8 回归实测 26/27）**：该断言假设测试账号 `kcbugtest@example.com`（uid=161）**尚未持有权益**，但该账号自 Step 6 起长期持有一份 `pack_light_off40`（剩余 5 次、active）用于权益链路验证，故「我的权益」区块不再显示空态。**属测试夹具过期，非功能回归**（其余 26 项含导航 5 项 / `#/pack` 接管 / 双档价格 / 余额开通端到端 / 深色窄屏**全部 PASS**）。若需复跑该脚本的空态分支，需先临时清空该用户的 grant。
