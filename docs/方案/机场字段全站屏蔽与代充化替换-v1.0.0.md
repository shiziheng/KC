## 1. 背景与根因

### 1.1 现象
用户截图（`/#/order/202610122104396073583767`）「商品信息」卡：

```
产品名称：ChatGPT Plus 一个月
类型/周期：月付          ← 机场模型字段
产品流量：100 GB         ← 机场模型字段
```

### 1.2 根因（源码级证据）

字段渲染于 Xboard 编译产物 `umi.js`（订单详情页模板，偏移 ≈1226214）：

```js
// 商品信息卡三行结构（编译后的渲染函数）
div[uG][ div[dG]"产品名称："  div[pG]{plan.name} ]
div[hG][ div[fG]"类型/周期：" div[vG]{period→月付/季付/…} ]
div[mG][ div[gG]"产品流量："  div[bG]{plan.transfer_enable + " GB"} ]
```

- `类型/周期` 值来自 `order.period`（订阅周期枚举），`产品流量` 值来自 `plan.transfer_enable`（机场流量配额）——均为**订阅制机场数据模型的固定字段**，与代充业务无关。
- **KC 侧代码无法直接改**（编译产物不可改）；不改编译产物即可消除的唯一路径 = **运行时语义过滤器**（本方案核心）。

## 3. 技术策略：四层防线

```
L1 静态审计（已完成）  编译包 = 唯一文案源 → 全量枚举 → 词典
L2 声明式规则表（新增）  一处配置：字段→动作（保留/替换/屏蔽+映射）
L3 运行时过滤器（新增）  标签驱动的语义匹配引擎（全站、幂等、自愈）
L4 词典断言回归（新增）  Headless 遍历全页 → 可见文本扫词典 → 0 命中即过
```

### 3.1 L1 静态审计（已执行，产出即本方案 §1.3）

编译产物是全部 UI 文案的**唯一来源**——因此对编译包做一次全量词典扫描，即可穷举"可能出现的机场字段"，不依赖人工逐页浏览。

### 3.2 L2 声明式规则表（设计）

新增于 `kc_theme_inject.html` 的独立段 `S4 · 机场字段过滤器`。**新增字段 = 规则表加一行**，无需改引擎：

```js
// 周期枚举 → 代充语义映射（订单详情/列表共用）
var KC_FF_PERIODS = {
  '月付':'30 天', '季付':'90 天', '半年付':'180 天',
  '年付':'365 天', '两年付':'730 天', '三年付':'1095 天', '一次性':'单次'
};
var KC_FF_RULES = {
  // ① 行级（label:value 结构，如详情页商品信息卡）
  rows: [
    { label:'类型/周期', rename:'服务周期', map:KC_FF_PERIODS },
    { label:'产品流量', rename:'交付方式', value:'卡密自动发放' },
    { label:'旧订阅折抵金额', hide:true },
    { label:'折抵', hide:true }
    // M2 后追加：{ label:'流量邮件提醒', hide:true }, ...
  ],
  // ② 列级（表格 th，如订单列表）
  cols: [
    { label:'周期', rename:'服务周期', map:KC_FF_PERIODS }
  ],
  // ③ 节点级（按钮/链接，按精确文案）
  nodes: [
    { text:'查看使用教程', hide:true }
    // M2 后追加菜单项处理（节点状态/流量明细/使用文档，见 §4.3）
  ]
};
```

### 3.3 L3 运行时过滤器（引擎设计）

| 设计点 | 规格 |
|---|---|
| **匹配原则** | **按可见文案精确匹配**（label 元素的文本 = `"{规则label}："`），不依赖编译类名（类名是压缩产物不可读且可能变）。一行/一列的判定：元素有 2 个子元素且首子元素文本以 `：` 结尾 |
| **动作** | `hide`（`display:none` + 标记）/ `rename`（改 label 文案）/ `map`（按映射表改值文案；未命中映射表则原样保留兜底）/ `value`（固定值改写） |
| **幂等** | 处理后打 `data-kc-ff="<ruleId>"` 标记；再扫时先查标记/先比对目标文案，已达标跳过 |
| **不用 remove()** | ⚠️ **对 Vue 管理的节点只隐藏、不删除**——Vue 虚拟 DOM 更新时找不到被删节点会报 patch 错误。隐藏可逆、更安全 |
| **触发时机** | ① boot 后首扫 ② `hashchange`（复用既有监听链）③ 路由进入订单页后 800ms×15 轮询（复用 `ensureOrderPaint` 模式）④ 全局心跳 1000ms（订单/个人中心路由才真正扫描，其余路由立即 return，成本≈0）⑤ 主内容区 `MutationObserver`（childList+subtree，防抖 60ms，**绝不开 characterData**——既有代码已实测自回调风险） |
| **自愈** | Vue 因订单轮询/重渲染刷回原文案时，心跳与观察器会再次应用（字段先恢复再被改回，窗口 <1s；防闪见下） |
| **防闪（FOUC）** | 字段出现到被替换之间的窗口。方案：① 观察器 + 短轮询把窗口压到 <300ms；② M1 实测 DOM 后，如结构稳定则追加**作用域预藏 CSS**（仅订单详情首卡第 2/3 行、按 nth-child 预藏，过滤器成功改写后再显示）——是否启用按实测决定 |
| **作用域** | 全站（除 `#/login`），规则文案均为精确整段匹配，无部分匹配误伤 |

**为什么不用其他方案**：

- **改编译产物（umi.js 补丁）**：违背项目红线（只许①保命补丁②插件 API③壳层菜单）；Xboard 升级/主题更新即丢失；现有 4 处保命补丁均为后端 PHP，前端编译补丁无既有维护设施。❌
- **纯 CSS 隐藏**：CSS 无 `:contains()`，无法按文案选中元素，只能按 nth-child 盲匹配（脆弱且无法做"替换"）。仅作防闪辅助。❌
- **后端/插件改接口**：字段是前端模板内数据渲染（period / transfer_enable），后端改不掉渲染逻辑。❌

### 3.4 L4 词典断言回归（"一次性"的证明机制）

新增 `tools/check-airport-lexicon.js`（复用 Chrome CDP 一次性 profile 模式）：

1. 登录测试账号 → 遍历全部可达路由（dashboard/plan/order/order 详情/profile/invite/ticket/knowledge/node/traffic）
2. 每个页面取 `document.body.innerText`，按**机场词典**断言（`流量|订阅|节点|折抵|续费|倍率|机场|设备限制` 等，白名单除外）
3. 登录/未登录两态各跑一遍；输出 `logs/airport-lexicon-report.json`
4. **判定**：0 命中 = 通过。以后任何 Xboard 升级、文案变化、新增页面，重跑即知有没有漏网

## 4. 替换文案设计（代充化）

### 4.1 订单详情 · 商品信息卡（核心）

| 原 | 新（推荐） | 备选 |
|---|---|---|
| 类型/周期：月付 | **服务周期：30 天** | 开通方式：自动代充 |
| 产品流量：100 GB | **交付方式：卡密自动发放** | 兑换方式：支付后自动发卡 |

设计依据：本业务支付成功后 → 自动发卡（CDK）→ 用户兑换，故「交付方式：卡密自动发放」与事实一致；「服务周期：30 天」把订阅周期转换为代充语境的服务时长。

### 4.2 周期映射表（详情页 + 列表页共用）

月付→30 天 · 季付→90 天 · 半年付→180 天 · 年付→365 天 · 两年付→730 天 · 三年付→1095 天 · 一次性→单次 · 未命中→保留原文（兜底）

### 4.3 菜单清理

- 移除：头像下拉 + 移动抽屉中的「节点状态」「流量明细」「使用文档」三链接（删除 KC 自建 DOM，安全）
- 保留：个人中心 / 我的邀请 / 我的工单 / 兑换卡密 / 退出登录

### 4.4 页面级兜底（M3 可选）

`#/node`、`#/traffic`、`#/knowledge` 直连访问 → 重定向 `#/dashboard`（约 10 行；防"收藏夹/历史记录"直达机场页）。推荐做，可裁剪。

## 5. 实施步骤（分段，每段停下确认）

### M1 · 引擎 + 已知规则 + 部署（覆盖订单两页）

1. Headless 抓真实 DOM（登录测试号 → 订单详情/列表），产出选择器基线（验证 §3.3 的行结构判定）
2. `kc_theme_inject.html` 新增 S4 段（规则表 + 引擎 + 触发挂载 + 菜单清理）；防闪 CSS 按实测决定
3. 静态自测：`node --check` 等价的脚本解析（项目既有 `new Function` 校验模式）+ 引擎 dry-run 单测
4. 部署：`docker cp` 三源 → `php xboard-set-custom-html.php` → `xboard-theme-state.php` 零漂移核查
5. 实机验证：headless 走查订单详情/列表（截图 + DOM 断言）；**手工复核**结账/关闭订单/取消等按钮功能不受影响
6. 版本六步：VERSION→v1.22.0 / 产品全景 / CHANGELOG / README 同步

### M2 · 全站断言审计 + 补齐

1. 交付 `tools/check-airport-lexicon.js`，全路由两态跑断言
2. 按报告补齐规则（如个人中心通知区、意外命中页）
3. 复跑到 0 命中；报告归档 `logs/`

### M3 ·（可选）直连拦截 + 防闪增强

1. `#/node` `#/traffic` `#/knowledge` 路由重定向
2. 若 M1 未做防闪且实测有可见闪动 → 补作用域预藏 CSS

### 5.2 部署流程（复用既有资产）

```
docker cp tools/kc_theme_inject.html xboard:/www/kc_theme_inject.html
docker exec xboard php /www/xboard-set-custom-html.php      # 三源拼接 → live custom_html
docker exec xboard php /www/xboard-theme-state.php          # 零漂移核查（len/md5）
```

### 5.3 ⚠️ 连带上线事项（重要）

线上主题（custom_html）停留在 **v1.13 版本**（`has_promo_row=0`）——v1.14 主题增量（优惠行全局开关、类型标、游客套餐区真实数据渲染等）**从未部署**（当时 Docker 引擎故障，后未补）。
**本轮部署会把 v1.14 增量一并带上线**，因此：

- 部署后需**一并验收** v1.14 特性（优惠行开关 / 类型标 / 游客浏览）
- 若不想连带 → 需先从本地源摘出 v1.14 增量再部署（不推荐：多做一步且 v1.14 是已批准的成果）
- §8 待拍板项 5 需要用户确认这一点

## 7. 风险与回滚

| 风险 | 等级 | 缓解 |
|---|---|---|
| Vue 重渲染覆盖替换（订单轮询刷新） | 中 | 心跳 + 观察器自愈；幂等标记 |
| 删除 Vue 节点致 patch 报错 | 高（已规避） | 只隐藏不删除（§3.3 规格） |
