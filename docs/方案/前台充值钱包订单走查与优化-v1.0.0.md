## 〇、一句话结论

**充值功能目前等于不可用**（有有效订阅的用户点了充值只会被劝去"看别的套餐"）；**订单金额全部显示 0.00**（用户无法核对任何一笔消费）；**已完成订单还带"取消"按钮**；**余额 $9.44 无任何流水可查**。这四条是必须先修的，其余是体验债。

## 二、需要你拍板的 3 个决策（其余我按专家判断定）

**决策 1：余额充值留还是砍？**
- 方案 A（**我推荐**）：**保留余额，正名为"账户余额"**——所有支付都走余额（下单时余额优先、不足引导去充值），USDT 只是"给余额充值"的通道。充值弹窗改为「用 USDT 充值余额」+ 任意金额；文案统一口径。
- 方案 B：**彻底砍掉余额**——所有订单直接 USDT 支付，清零历史余额、归档 9 个充值档位、隐藏所有余额/充值相关 UI。最简单，但已发出去的余额与存量订单要处理，且"余额优先"的既有逻辑要拆。

**决策 2：待支付订单的规则？**
- 我推荐：**30 分钟未支付自动关闭**（释放锁定），列表显示倒计时；已取消/已关闭单进"历史"tab 只读。

**决策 3：卡密→开通要不要做"一键带入"？**
- 我推荐：订单详情「去开通」跳转兑卡页时**自动带入卡密与订单上下文**（Session 仍需用户粘贴，安全上不代填），减少"复制→粘贴"丢失。属体验增强，非阻断。

## 三、优化方案（分四批，每批可独立发版）

### 第一批 · 业务口径定 + P0 修复（建议 v1.27.0）
1. **充值可达**：移除"已有有效订阅→无需充值"的劝退逻辑，改为任何时候点充值都能进入充值页；"有订阅"仅作为一句提示（如"你已有订阅，仍可充值余额备用"）。
2. **余额口径统一**（按决策 1 落文案）：下单确认页、充值页、订单详情三处说同一句话——"可用余额支付，余额不足时用 USDT 直付"（或"余额已改为账户余额，支付时自动优先抵扣"）。
3. **金额显示修复**：订单列表/详情按支付方式显示实付——余额支付 `$15.00（余额）`、USDT 支付 `$15.00（USDT）`；充值类订单显示"到账 $14.00"而非 0.00。
4. **订单操作按状态收紧**：已完成 = 只有「查看详情」；待支付 = 「继续支付 / 取消」；已发货待开通 = 「去开通 / 申请售后」。
5. **详情状态单一语义**：顶部状态词与下方区块联动（已发货→显示"待开通"作为下一步行动，而不是第二个"状态"）。
6. **弹窗随路由关闭**：全局浮层注册 hashchange 监听，切页自动关闭（顺手覆盖兑换卡密、公告等所有浮层）。
7. **充值档位去重**（若走方案 A）：$1/$2/$7/$14 各留一个 + 自定义金额（最小 $1）。

### 第二批 · 对账与状态机（建议 v1.28.0）
1. **钱包流水页**（`#/wallet`）：充值 / 消费逐条（时间、金额、方向、关联单号、变动后余额），余额卡片 + 明细表；入口从顶栏余额与个人中心两处进。
2. **订单状态筛选 tab**：全部 / 待支付（带数量角标）/ 已完成 / 已关闭。
3. **待支付超时机制**：30 分钟自动关闭 + 倒计时展示 + "恢复支付"（如 BEpusdt 订单未过期）。
4. **详情页时间线**：下单 → 支付 → 发卡 → 开通 四节点（时间 + 说明），替代现在分散的文案块。
5. **售后入口**：详情页底部「申请售后 / 联系客服」直达工单并预填订单号。

### 第三批 · 导航与流程压缩（建议 v1.29.0）
1. **导航瘦身**：顶栏收敛为「首页 / 商品 / 我的订单 / 余额（充值）」四项；"代充/成品号/建站服务"合并进"商品"的分页；浮动按钮去掉"充值"（顶栏已有），只留"兑换卡密"。
2. **命名买家化**：「代充」→「商品」或「套餐」；"卡密兑换"保留但文案改为"我有卡密，兑换开通"。
3. **开通链路压缩**：「去开通」带卡密与订单号跳兑卡页，自动填充只读卡密框（Session 仍手工粘贴）。
4. **订单列表优化**：服务周期与金额同列紧凑展示；长订单号支持点击复制。

### 第四批 · 充值与细节体验（建议 v1.30.0）
1. 充值页增「到账预计时长」「支付方式说明」「订单可在钱包查到」等信任要素。
2. 首页公告条改为可关闭且只展示一次。
3. 全站金额单位统一（$ 两位小数，余额/价格/流水一致）。
4. 空态设计：无订单/无流水/无商品的引导文案与插画统一。

## 四、验收方式

每批开发后跑一次走查脚本（`_v127_ux_trial.js` 扩展版），验收标准：
- 充值页对任意账号可达，且能完成一次 USDT 充值到账（沙盒）
- 订单列表金额与数据库一致（0.00 归零）
- 已完成订单无取消按钮；待支付有倒计时与取消
- 详情页顶部状态唯一、与下一步行动一致
- 钱包流水与订单金额可对账
- 切页无残留浮层
