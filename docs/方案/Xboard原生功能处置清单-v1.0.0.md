## 一、目的

Xboard（过渡期商城壳）自带一批**机场原生功能**。它们是"沿用旧壳"的副作用，与「ChatGPT 代充」定位无关。本清单把每一项**显式定调**为「保留 / 隐藏 / 外链」并给出理由，避免：

1. 迭代时**误删**真正在用的功能（如工单售后通道）；
2. 迭代时**误加回**已隐藏的机场功能（如节点、流量）；
3. 交接时**没人知道**某入口为什么在/不在。

> **定调 = 唯一事实源**。与散落的历史讨论冲突时以本清单为准。

| 4 | **节点 node** | **隐藏** | 机场专有概念（服务器节点分组），代充平台无节点语义；属[产品全景.md](file:///d:/tools/KC-PAY-GPT/docs/产品全景.md)「明确不做：Xboard 的节点/流量/订阅链接/客户端」 | sidebar 无「节点管理」；`#/node` → `#/dashboard` |

## 三、保留面的「代充化」要求

被**保留**的功能（工单 / 知识库 / 邀请）必须满足：

1. **可见文本 0 命中机场词典**：`订阅|节点|流量|折抵|倍率|权限组|在线设备|设备限制|CNY|机场|月上传|月下载|线路|中转`。
2. **金额一律美元($)**：不出现 `¥`、`CNY`、`元`。
3. **身份化术语禁用**：不出现「会员 / 等级 / 升级 / VIP」，统一「权益包」。

> 保留 ≠ 原样照搬。保留的是**能力入口**，呈现层必须换成代充语言。

### 保留面去向（v1.46.0 · Stage 3.7 已落地）

Xboard 退场后，三项保留功能的**入口迁到 KC 原生主站前台** `public/site/index.html` 的页脚「帮助与支持」行：**工单支持 / 使用文档 / 邀请好友**。

| 保留面 | 退场后去向 | 未配外链时（原生回落） |
|---|---|---|
| 工单 ticket | 外链 `ticket_url`（运营可在租户品牌 `kc_tenant_brand.extra_json` 配置） | 引导到「我的订单 → 订单详情 → 申请售后」+「联系客服」 |
| 知识库 knowledge | 外链 `kb_url`（可选） | 滚到主站首页「常见问题」（v1.44.0 已建 FAQ） |
| 邀请 invite | 外链 `invite_url`（可选） | 弹层说明「邀请佣金在平台内结算、不对外开放提现」—— **佣金不出圈**，与「明确不做：分销提现和推广看板」一致 |

> 结论：三项保留功能的**去向已明确**（外链 or 原生回落），满足 [Stage3切换前对照清单](file:///d:/tools/KC-PAY-GPT/docs/方案/Stage3切换前对照清单-v1.0.0.md) §五 前置条件 5。

## 五、变更纪律

1. **隐藏项不得被再加回**。若某次迭代需要「节点/流量/订阅」入口，必须先改[产品全景.md](file:///d:/tools/KC-PAY-GPT/docs/产品全景.md)「明确不做什么」并说明理由，再改本清单。
2. **保留项的文案**受词典守护，改动后必须重跑 `check-admin-airport.js` 与 `check-airport-lexicon.js`。
3. 本清单的**定调**是 Stage 3（v2.0.0 Xboard 退场）执行「原生功能落地」的输入：隐藏项随下线自然消失，保留项需迁到 KC 自有前台。
