# 商品配置体验重构方案 v1.0.0

> **方案编号**：`SP-2026-10-13-v1.0.0`　**状态**：待评审（本版本只出方案，不执行开发）
> **面向**：运营者（非技术）视角的商品配置全流程重设计
> **相关**：`SP-2026-10-11-v1.0.1`（三层解耦，背景架构）——本方案是它的**体验层修正**：架构不动，操作面重做

---

## 一、为什么难用：现状诊断（实测证据，2026-10-13）

以"上架一个 ChatGPT Plus 月卡"为例，实测（`logs/v125-ux/`）当前流程为：

```
Xboard 后台「套餐管理」—— 商品名/价格/周期/说明（商城真正卖的数据）
KC 后台「上游管理」    —— 查货源、查"套餐键"（plus）
KC 后台「商品与资费」  —— 填 code、绑上游 code、绑套餐键、再开"资费规则"配价格
KC 后台「商品卡片」     —— 第三个地方配展示、再点"全部同步到 v2"
（插件 packages 映射）  —— 数据层隐含步骤，界面从未引导
```

**2 个后台、4+ 个页面、10 余个技术字段**，任何一处漏配都会"看着配好了但商城不对"。具体问题：

| # | 问题 | 实测证据 |
|---|---|---|
| P1 | **要求运营输入技术码** | 新建 SKU 表单：`code（唯一，小写字母/数字/下划线）`、`上游 code`、`上游套餐键`——全部要求手输英文码 |
| P2 | **跨页引导** | 弹窗底部提示："⚠ 上游套餐键必须存在于「上游管理」目录中；新建后用「资费规则 → 整体替换」配置价"——要求用户记住键名、跳页、再回来 |
| P3 | **一个商品拆三段配** | 商品（SKU）→ 资费规则（另一个弹窗）→ 商品卡片（另一个菜单）——同一件商品的三个属性互不相邻 |
| P4 | **配了不生效 / 不知道谁生效** | 页面明写"与 v2_plan.prices 解耦""R3 起由前台切换读法"——商城售价实际仍由 Xboard 套餐决定；KC 侧配置对商城不生效 |
| P5 | **界面文案是开发注释** | 页面顶部："KC 视图的 SKU 配置面（v1.16.0；SP-2026-10-11-v1.0.1 §R2）。每个 SKU 引用上游套餐键……未改前台。"——面向开发，不是面向运营 |
| P6 | **列表信息层级技术化** | 行信息：`xplan_1｜代充｜已启用｜规则数: 1｜mock_zovo / plus｜v1.16.0 回填自 v2_plan id=1`——没有"卖多少钱"这个运营第一关心的数字 |
| P7 | **术语混用** | 上游/SKU/资费规则/卡片/规则数/manual/month/priority——五套词汇体系 |

**一句话**：这是"给开发配的界面"，不是"给运营配的界面"。

## 二、目标设计：运营只做 3 件事

**设计原则**：
1. **业务语言**——界面只说"商品、价格、货源、上架"，不出现 code/键/manual 等词
2. **单线流程**——一个商品从头到尾不离开一个流程（向导或详情页）
3. **选择代替输入**——货源从列表里"挑"，编号系统自动生成
4. **保存即生效**——保存后商城立即可见可买（写同步），不需要"再点一次同步"
5. **所见即所得**——定价时右侧实时预览商城卡片

**新流程总览**：

```
现在：Xboard 套餐 → KC 货源 → KC SKU → KC 资费 → KC 卡片 → 手动同步     （6 步 2 后台）

未来：KC 后台「商品管理」→ ①选货源 → ②定价 → ③上架信息 →「保存并上架」 （3 步 1 处）
                                              ↓ 自动完成
       建商品 + 建价格 + 建展示 + 同步到商城（Xboard 数据自动写入）
```

**导航变化**（KC 后台运营区）：

| 现在 | 未来 |
|---|---|
| 商品与资费（技术表单） | → **商品管理**（列表 / 新建向导 / 商品详情） |
| 商品卡片（第三处配置） | → 合并进「商品管理」的商品详情页 |
| 上游管理（保留） | → 上游管理（职责不变，文案运营化） |
| 权益（保留） | → 权益（保留，文案运营化） |

## 三、新界面设计（字段级）

### 3.1 商品列表页（日常首页）

每行 = 一个商品，展示运营最关心的 4 件事：

```
┌──────────────────────────────────────────────────────────────────────┐
│  商品管理                                [ 刷新 ]  [ + 新建商品 ]      │
├──────────────────────────────────────────────────────────────────────┤
│  ChatGPT Plus 一个月          $15.00 /月      在售中  ●               │
│  货源：ChatGPT Plus（月付）· 正常        今日 3 单 / 累计 32 单        │
│  [ 编辑 ] [ 复制 ] [ 下架 ]                                          │
├──────────────────────────────────────────────────────────────────────┤
│  余额充值 $14                 $14.00 起       在售中  ●               │
│  货源：余额充值（未绑货源）              今日 0 单 / 累计 0 单         │
│  [ 编辑 ] [ 复制 ] [ 下架 ]                                          │
└──────────────────────────────────────────────────────────────────────┘
```

- **不再显示**：xplan_1、规则数、mock_zovo / plus、回填来源注释
- 状态点按切换（在售中 ↔ 已下架），下架后商城立即不可见
- "未绑货源"用橙色提示——只影响"换货源/成本核算"能力，不阻塞销售

### 3.2 新建商品向导（第 1 步：选货源）

```
┌── 新建商品 ────────────────────────── ①选货源 ── ②定价 ── ③上架信息 ──┐
│  从你的货源里挑一个商品（列表来自「上游管理」的目录）                    │
│                                                                        │
│   ┌────────────────┐  ┌────────────────┐  ┌────────────────┐          │
│   │ ChatGPT Plus   │  │ ChatGPT Go     │  │ ChatGPT Pro 5x │          │
│   │ 订阅 · 月付     │  │ 订阅 · 月付     │  │ 订阅 · 月付     │          │
│   │ 货源：ZovoCard  │  │ 货源：ZovoCard  │  │ 货源：ZovoCard  │          │
│   └────────────────┘  └────────────────┘  └────────────────┘          │
│   …（积分类商品分组显示）                                              │
│                                                                        │
│   ▸ 高级：手动指定货源（上游 + 商品键）                                 │
│   [ 取消 ]                                            [ 下一步 → ]     │
└────────────────────────────────────────────────────────────────────────┘
```

- 所见即所选：卡片直接来自上游目录，**不需要知道任何"键"**
- 高级项默认折叠（给技术员留口子，运营不用碰）

### 3.3 第 2 步：定价（核心：就填一个数）

```
┌── 新建商品 ───────────────── ①选货源 ── ②定价 ── ③上架信息 ──┐
│  计费周期：[ 月付 ▼ ]（已按货源自动带出，可改为「一次性」）        │
│                                                                │
│  售价 ★         $ [ 15.00 ]   /月                              │
│                                                                │
│  ▸ 高级定价（可选）                                             │
│     划线原价    $ [ 20.00 ]    商城显示「原价 $20」              │
│     活动价      $ [      ]   活动时段 [   ] ~ [   ]             │
│     会员折扣    [ 20 % ]     持有权益的用户自动打折               │
│                                                                │
│              ┌─ 商城预览（实时）──────────────┐                  │
│              │ ChatGPT Plus 一个月            │                  │
│              │ 官方渠道直充，支付后自动发卡密   │                  │
│              │ $15.00/月   原价 $20          │                  │
│              │ [ 立即办理 ]                   │                  │
│              └───────────────────────────────┘                  │
│   [ ← 上一步 ]                            [ 下一步 → ]          │
└────────────────────────────────────────────────────────────────┘
```

**"怎么给商品配资费"的答案 = 只填「售价」一个必填项**。三层价格（对应现有引擎，不露术语）：

> 补篇提示：若该商品还要对外分销（供下游 API 按上游成本加价售卖），「定价」区会多出一个「**API 分销定价**」开关块（加价比例/固定额 + 保护价 + 报价模拟器）——完整设计见《双模式定价与对外分销 API 设计 v1.0.0》（`SP-2026-10-13-API-v1.0.0`）。商城固定价与 API 加价价互不影响。

| 运营看到的 | 底层能力（不动） | 说明 |
|---|---|---|
| 售价（必填） | `manual` 规则 | 常规售价 |
| 划线原价（可选） | 展示字段 | 商城划价 |
| 活动价 + 时段（可选） | `promotion` 规则 + 有效期 | 到期自动回落售价 |
| 会员折扣 %（可选） | `entitlement` 规则 | 持有权益用户比价自动取低 |

### 3.4 第 3 步：上架信息 + 收口

```
┌── 新建商品 ───────────── ①选货源 ── ②定价 ── ③上架信息 ──┐
│  商品名称 ★   [ ChatGPT Plus 一个月 ]（已预填货源名，可改）  │
│  一句话卖点   [ 官方渠道直充，支付后自动发放卡密 ]（预填）    │
│  分类标签     [ 代充 ]（预设下拉：代充 / 充值 / 权益）       │
│  ▸ 商城卡片样式（可选）                                      │
│     权益清单（每行一条）  [ 官方直充\n支付后自动发卡\n… ]     │
│  上架状态     ● 立即上架    ○ 先存草稿                      │
│                                                            │
│   [ ← 上一步 ]                          [ 保存并上架 ]      │
└────────────────────────────────────────────────────────────┘
```

**「保存并上架」一键自动完成**（用户无感）：
1. 创建商品（编号自动生成，如 `xplan_16`）
2. 写入价格（售价 + 可选活动/会员价）
3. 写入商城展示卡片
4. **同步到商城**（写 Xboard：商品名/价格/显示 + 卡片 + 插件货源映射）→ 商城立即可见可买

### 3.5 商品详情页（后续编辑——一页改全部）

```
ChatGPT Plus 一个月                      [在售中 ●]  [下架]  [复制]
─────────────────────────────────────────────────────────────────
📦 基本信息   名称 / 卖点 / 标签 / 上架状态
💰 价格       售价 / 活动价 / 会员折扣（改完即存，商城即时生效）
🖼️ 商城展示   卡片副标题 / 权益清单 / 按钮文案（右侧实时预览）
🔗 货源       ChatGPT Plus（月付）· ZovoCard   [ 更换货源 ]
⚙️ 高级（折叠） 内部编号 / 同步状态 / 变更记录
─────────────────────────────────────────────────────────────────
每次保存 → 自动同步商城；顶部显示"已同步到商城 ✓ 刚刚"
```

原「商品卡片」菜单取消（功能并入本页 3 区），原「商品与资费」菜单被「商品管理」取代。

## 四、关键机制：让配置真正生效（写同步）

现状（P4）是"配了不生效"的根源。本方案把 **UX 重构与生效链路一起解决**：

| 阶段 | 做法 | 效果 |
|---|---|---|
| **阶段 A（本次方案包含）** | 商品保存时，服务端**自动写同步**：Xboard `v2_plan`（名称/价格/显示/卡片）+ 插件商品映射 | 商城立即生效；运营不再碰 Xboard 套餐管理 |
| 阶段 B（后续评估） | 商城商品页改直读 KC 数据（BFF） | 彻底解耦；等阶段 A 稳定 ≥1 个版本 |

阶段 A 的技术口径（已有基础设施，风险可控）：
- 复用现有 `sync-to-v2` 能力（R3 已建），扩展为"保存即触发"
- Xboard 侧只写既有字段（`name/prices/kc_card/显示`），不新增表，不碰插件代码
- 幂等：同一商品重复保存 = 覆盖式更新
- 失败兜底：同步失败 → 商品页顶部红条"未同步到商城，点此重试"（不丢配置）

## 五、日常操作手册（重构后，7 个场景）

**① 上架一个新商品（约 2 分钟）**
1. 商品管理 →「+ 新建商品」
2. 第 1 步：从货源卡片里点选（如 ChatGPT Plus）
3. 第 2 步：填售价 $15.00 → 下一步
4. 第 3 步：确认名称/卖点（已预填）→「保存并上架」
5. 完成：商城立即可见可买

**② 调价（约 30 秒）**
商品管理 → 找到商品 →「编辑」→ 价格区改数字 → 保存（商城即时生效）

**③ 做活动**
编辑 → 价格区 → 填活动价 + 起止时间 → 保存（到期自动恢复原价）

**④ 下架 / 重新上架**
列表行「下架」点按；重新上架同样一键

**⑤ 更换货源**
编辑 → 货源区 →「更换货源」→ 从目录重新选 → 保存（商品名/价格/展示不动）

**⑥ 给会员发折扣**
编辑 → 价格区 →「会员折扣」填百分比；细粒度规则到「权益」页（保留）

**⑦ 复制商品（做同款不同价）**
列表「复制」→ 改名称/价格 → 上架

## 六、过渡期操作手册（**当前版本马上可用**，重构未上线前）

> 当前 v1.23.1 仍为双轨：**商城售价以 Xboard 套餐为准**；KC 侧为"货源与演进准备"。按以下步骤操作即可完成一次完整配置：

**场景：上架/调整一个商品**

| 步骤 | 在哪里 | 做什么 | 填什么 |
|---|---|---|---|
| 1 ★必做 | Xboard 后台 → 套餐管理 | 编辑/新建套餐 | 名称、月付价格、周期、说明、显示开关（**商城以这里为准**） |
| 2 建议 | KC 后台 → 商品管理（现名"商品与资费"） | 确认/新建对应商品，绑定货源 | 无需理解 code：名称写商品名；"上游 code"填 `mock_zovo`；"上游套餐键"填 `plus` |
| 3 建议 | KC 后台 → 商品卡片 | 编辑卡片 → 保存 → 点「全部同步到 v2」 | 副标题/权益清单/按钮文案 |
| 4 验证 | 商城商品页（游客窗口） | 确认显示与价格 | — |

**过渡期三个"别慌"**：
- KC「商品与资费」页价格**不改变商城售价**（商城看 Xboard 套餐）——这是双轨期的已知设计，重构后消除
- KC 里显示"未绑定上游"的商品不影响销售（只影响换货源/成本核算）
- 「资费规则」弹窗平时不用打开（重构后它被"定价"步骤取代）

## 八、本方案已做出的决策（无需再选）

1. 操作面 = **KC 后台**（自建可控；Xboard 后台保持"代充运营"入口直达）
2. 术语 = **商品 / 价格 / 货源 / 上架**；"上游"保留（沿用你已有叫法）
3. 资费 = 一个必填「售价」+ 三个可选项（原价/活动价/会员折扣），底层引擎不动
4. 生效 = **保存即写同步商城**（阶段 A 先行）；读切换（阶段 B）后续评估
5. 老页面不删（直连保留给技术管理），菜单只露新入口
