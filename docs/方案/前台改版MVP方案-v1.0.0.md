## 二、优化策略（五条原则，全程遵守）

1. **配置驱动，代码零硬编码。**
   品牌/权益包/商品权益价/文案全部走已建好的 `GET /api/public/site-config`；前端只写**渲染逻辑**。"省 $X / 净赚 $Y / 每次成本 $Z"这类**计算文案由前端按数字实时生成** —— 后台改一个数，全站文案自动跟。这是上一轮已搭好的系统，本轮直接消费。

2. **地基先行，一次投入全站生效。**
   先改全局配色 token（`:root` 里的 `--kc-brand` 三色），全站所有用它的组件立刻变风格；**不逐页调色**。

3. **压制而非删除，随时可回退。**
   旧版门户内容（"两条路径""选择适合你的套餐"）用 CSS/JS **压制隐藏**，不删代码。新页面出问题，撤掉压制层即回到旧版 —— 零风险试错。

4. **每步独立可验证、可回退。**
   每一步有**验收清单 + 截图证据**，做完确认再进下一步。出问题只回滚当前步，不牵连已完成步。

5. **进度单一事实源。**
   进度只写在 `docs/改版进度.md`。任何协作者（含换模型）开工前读它 → 执行"下一步" → 更新"已完成"。**不依赖任何对话上下文。**

## 五、进度同步机制（换模型也能接续）

进度写在 **`docs/改版进度.md`**，它满足：

1. **自包含**：不引用对话内容，含全部关键决策、文件路径、命令、已知坑。
2. **单一"下一步"**：任何时刻只有一个明确的"下一步"，接手者照做即可。
3. **每步留证**：验收截图路径写进状态文件。
4. **变更即更新**：每完成一步立即更新（这是铁律）。

**任何协作者的标准动作**：读 `docs/改版进度.md` → 执行"下一步" → 按验收清单自测 → 截图 → 更新状态文件 → 汇报。
