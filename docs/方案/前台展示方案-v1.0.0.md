## 一、判断口径（我怎么判「是否可用」）

一条前台展示方案要同时满足四个硬条件才算「可用」，缺一即判不可用：

1. **任务可达**：用户 3 秒内知道「这是干什么的」「我该点哪」；从首屏到完成一次充值/购买，点击数不超过 3 次进入关键页。
2. **金额可信**：涉及金额、网络、期限的信息对比度最高、字号最大、无歧义（这是本产品的核心信任面）。
3. **口径不破**：不破坏既有产品铁律 —— 导航恒 5 项（代充/成品号/建站服务/权益包/我的订单）、全站禁用「会员/等级/升级/VIP」、统一用「权益包」、金额一律 `$`。
4. **实现成本可控**：单文件（`public/site/index.html`）+ 纯 CSS/原生 JS 可落地，不新增运行时依赖、不改镜像。

### 2.1 视觉基调（实测取色）

| 项 | 实测值 | 说明 |
|---|---|---|

| 正文色 | `#FFFFFF` / 次级灰 | 高对比白字 |
| **强调色** | `rgb(118,185,0)` ≈ `#76B900` | 亮柠绿（NVIDIA 绿一类），用于标题第二行、按钮、卡片描边、发光 |
| 卡片底 | `rgba(20,24,22,.7)` | 半透明深绿灰 |
| 卡片描边 | `rgb(30,42,30)` | 极暗绿描边 |
| 圆角 | 卡片 `16px` / CTA 卡 `8px` | 大圆角、克制 |
| 字体栈 | `Microsoft YaHei, PingFang SC, -apple-system, Segoe UI, Roboto…` | 中文优先，无自托管字体 |
| 特殊效果 | 绿色地球/粒子背景 + 卡片外发光 `0 0 22px rgba(118,185,0,.13)` | 科技感来源，仅首屏使用 |

### 2.2 信息架构（整页顺序）

1. 顶栏：logo 左；导航「AI 订阅 / 推广合作」；右侧 语言 / 币种 / 登录·注册（绿色实心胶囊）
2. **Hero**：两行大标题（第一行白、**第二行绿并在视觉上「压过」第一行**）+ 一句副标题 + 一张**发光描边 CTA 卡**（图标+标题+一句卖点+右箭头）
3. **社会证明**：客户 logo 墙（Oracle/Microsoft/ByteDance/Meta/amazon/IBM/airbnb）+ 3 个数据指标（99.99% 稳定运行 · 616,092+ 开发者 · 10B+ 请求量）
4. 区块标题（「AI 与流媒体会员订阅、充值及账号」）+ 一段说明
5. **3 张能力卡**（图标 + 标题 + 两行说明）：AI 会员订阅与账号充值 / 视频与音乐流媒体订阅 / 账号与灵活交付方式
6. 安全提醒条（绿色左边框，一条）
7. **常见问题**（FAQ 手风琴，7 条，绿点图标）
8. 页脚：三列链接（关于 / 帮助 / 其他）+ 支付方式与语言 + 版权/ICP 备案
9. Cookie 同意弹窗（右下）

### 2.3 我看到的优点（值得借鉴）

- **标题层级极清晰**：两行标题用「颜色」而不是「字号」制造层次，扫读成本极低。
- **首屏只有 1 个主 CTA**（发光卡），没有并列按钮争抢注意力。
- **信任前置**：logo 墙 + 指标区把「可信」放在价格之前，符合工具类产品的下单心理。
- **卡片克制**：统一圆角/描边/内边距，深色下用「描边 + 微发光」代替阴影，避免了深色主题里最容易脏掉的阴影。
- **FAQ 手风琴**收页，把长尾疑问留在页尾，不干扰主路径。

### 2.4 我不建议照搬的部分（重要）

| 不照搬 | 原因 |
|---|---|
| 客户 logo 墙（Oracle/Meta…） | 我们是「ChatGPT 代充」单点工具，**用别家 logo 背书会被理解为代理关系**，既不真实也涉嫌品牌误用。**替换为「服务口碑/已服务订单数/开通成功率」类自证指标**。 |
| 大数字指标（61 万开发者 / 10B 请求） | 我们的量级不支持这种叙事，编数字等于自伤信任。**改为可核验的运营数据**（如「已交付 N 单 · 平均开通 X 分钟」），且必须从真实数据出。 |
| 绿色地球/粒子大背景 | 体量大、移动端耗电、与「付款页」气质不符；**只在首页 Hero 保留一层极轻的径向渐变**即可。 |
| Cookie 弹窗、语言/币种切换器 | 我们没有多语言/多币种（全站 `$`），加了反而是假功能。 |
| 全站通体深色 + 高发光 | 深色适合首页氛围，**但不适合金额与二维码**：收银台/充值页必须保证「金额、地址、倒计时」在强光环境下的可读性。⇒ **方案：深色为首页默认，金额类面板用「深色底 + 高对比白色大数字 + 低饱和描边」而非发光**。 |

## 三、KC 前台落地方案

### 3.1 配色 token（可直接替换 `:root`）

**深色（建议作为默认）**

```
--bg:#0D0E12;         /* 页面底 */
--card:#141817;       /* 卡片底（替代半透明，避免叠色脏） */
--line:#1E2A1E;       /* 描边 */
--line2:#2A3A2A;      /* 描边（hover） */
--text:#F2F5F3;       /* 主文字 */
--sub:#9AA69E;        /* 次级文字 */
--dim:#6C7A70;        /* 弱化文字 */
--brand:#76B900;      /* 强调色（亮柠绿） */
--brand-deep:#5E9600; /* 强调色 hover/按下 */
--brand-bg:#16210F;   /* 强调色浅底 */
--amber:#D9A441;      /* 警示（倒计时/注意） */
--red:#E5484D;        /* 错误/危险 */
--glow:0 0 22px rgba(118,185,0,.13); /* 仅用于 Hero CTA，禁用于金额面板 */
```

**浅色（保留为可选，用于收银/充值等需强光可读的场景）**：沿用现有
`--bg:#F6F7F5 / --card:#FFF / --line:#E4E5DF / --text:#1F2328 / --brand:#0F6E56`。

> 与现状关系：现有品牌准入色为 `--brand:#0F6E56`（墨绿）+ 支撑的 `#0B5341`，租户品牌色由 `kc_tenant_brand.primary_color/accent_color` 注入。本方案把**默认强调色换成更亮的 `#76B900`**，但**保留租户品牌色覆盖能力**（品牌注入优先级最高），避免破坏白标。

### 3.2 布局规格（首页）

| 区块 | 规格 | 与现状对应 |
|---|---|---|
| 顶栏 | 高 60px，logo 左、**导航恒 5 项**（代充/成品号/建站服务/权益包/我的订单）、右侧登录/退出 + 钱包入口，`position:sticky` | 现状已有，仅换 token |
| Hero | 标题两行：第一行 32/34px 常规色，**第二行同字号但用 `--brand`**；副标题一行 ≤ 44 字；**唯一主 CTA 卡**（描边 + `--glow`）：`选商品充值` → `#catalog` | 现状是单行 h1 + 双按钮 ⇒ 改为单 CTA |
| 信任条 | 一行 3 个指标（**真实数据**：已交付订单 / 平均开通时长 / 充值到账率），无 logo 墙 | 新增 |
| 能力 3 卡 | 「给已有账号充值（代充）」「买成品号」「建站服务」各一卡：图标 + 标题 + 2 行说明 + 「去看看」 | 现状有「为什么更省 / 三步完成」⇒ 合并保留其一 |
| 价格区 | 热门商品 4 卡（沿用现有双价卡：权益价大字 + 原价划线 + 「用 1 次权益 · 省 $X」） | 现状 `#homeGrid` 保留 |
| 权益包推介 | `#homePackGrid`（沿用） | 现状保留 |
| FAQ | 手风琴 6~7 条（充值多久到账 / 选错网络怎么办 / 金额为什么带 4 位小数 / 关闭充值页怎么办 / 支持哪些商品） | 现状 `.faq` 4 条 ⇒ 扩到 6~7 条并改手风琴 |
| 页脚 | 三列：帮助与支持（工单/使用文档/邀请）/ 关于我们 / 联系客服 + 版权 | 现状页脚「帮助与支持」行保留并扩列 |

### 3.3 组件规范（关键 5 条）

1. **主按钮**：实心 `--brand` + 深色文字（亮柠绿上必须用深字，白字对比不足）；hover 用 `--brand-deep`。
2. **金额**（充值/下单）：字号 ≥ 21px、字重 700、颜色 `--text`（**不用品牌色**）；辅助说明用 `--sub` 12px。
3. **危险/网络警示**：`--red` 文字 + `--red` 10% 底 + 1px 描边；文案保持现有「选错网络资金无法找回」。
4. **倒计时**：`--amber` 正文 + ≤5 分钟切 `--red` 脉冲（沿用现有 `.urgent`）。
5. **卡片**：`--card` + 1px `--line` + 16px 圆角；**阴影只在 hover 用**（深色下 `0 6px 22px rgba(0,0,0,.45)`）。

### 3.4 响应式

- ≤480px：能力 3 卡 1 列；Hero 标题 24px；CTA 卡整宽；FAQ 保持手风琴。
- 桌面 ≥1024px：Hero 内容居中最大宽 720px；商品网格 `minmax(240px,1fr)`。
- 深色下所有描边/底做 1 档提亮（`--line` → `--line2`），避免「深色里看不见边界」。

## 四、可行性结论（独立判断）

| 维度 | 判断 | 依据 |
|---|---|---|
| 视觉可移植性 | **可用** | 参考站无自托管字体、无 Canvas 依赖（除背景），配色是纯 CSS 变量，本项目单文件即可复刻 |
| 信息架构可移植性 | **部分可用** | Hero 双行标题、单 CTA、3 能力卡、FAQ 手风琴可直接用；logo 墙 + 大数字指标**必须替换**（见 2.4） |
| 与本产品铁律的兼容性 | **兼容** | 不改导航 5 项、不引入禁词、金额仍全 `$`；只动视觉与区块顺序 |
| 实现成本 | **低** | 估算：token 替换 + 首页区块重排 + FAQ 手风琴改造，集中在 `public/site/index.html` 一个文件；不新增依赖、不改镜像 |
| 风险 | **中低** | ①深色默认需回归「金额/二维码/倒计时」可读性；②亮绿与租户品牌色冲突（品牌注入优先，需保留覆盖）；③「信任条」若用假数据会反噬 ⇒ 必须真实数据或直接不做 |

**总判断：方案可用，建议分两步落地** —— 第一步只做「token 替换 + 首页区块重排 + FAQ 手风琴」（低风险、可回滚）；第二步再评估「信任条」（需真实数据支撑）与深色默认化。

## 五、不做什么（防误加回）

- 不做客户 logo 墙、不做语言/币种切换、不做 Cookie 弹窗、不做粒子/地球大背景。
- 不改导航项数量与文案（恒 5 项）、不引入「会员/等级/升级/VIP」、金额一律 `$`。
- 不在金额/地址/二维码面板上使用发光与半透明叠加。
- 不新增 npm 依赖、不改镜像。

## 六、验收口径（落地时需满足）

1. 首屏 3 秒可答「这是什么、点哪里」；主 CTA 唯一。
2. 375px / 768px / 1440px 三档零横向溢出、文字不竖排。
3. 深色下：金额对比度 ≥ 7:1（WCAG AAA 正文）、二维码在灰底上可扫（对比度 ≥ 4.5:1）。
4. 导航恰 5 项且序列为 代充/成品号/建站服务/权益包/我的订单；0 个禁词。
5. 充值/下单/兑卡三条主路径可用且 0 业务 console error（复用 `tools/_v290_frontend_ux_smoke.js` + `tools/_v2100_recharge_ux_demo.js`）。
