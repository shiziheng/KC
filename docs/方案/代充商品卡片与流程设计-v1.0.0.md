## 0. 一页结论

1. **卡片**：现状骨架已对齐参考站水准（主推标 / 副标题 / 价格+标签 / 功能清单 / 保障行 / 时效提示 / 立即办理 / 购买卡密）。本次设计**只增补 3 处**：① 优惠行启用规范（渲染已具备、当前为空）；② 右上角「代充」类型标（为三类商品共存铺路）；③ 底部服务 chips（常见问题 / 联系客服 / 批量优惠）。另同批打磨悬停与售罄态细节。
2. **流程**：把「立即办理（向导四步 · 主路径）」与「购买卡密（先买后用）」两条路径定成正式规格——步骤 / 状态 / 异常分支全部成文；并把**一直闲置的 `rules` 购买须知**接到向导「支付前」，对齐参考站的「购买前先确认」。
3. **一个待定**：商品页是否允许**游客浏览**（参考两站均允许；现状未登录会跳登录页）。建议开放：浏览不设门槛，点「立即办理」再登录并自动续接。
4. **改动量级：小**。集中在主题注入层（1 个文件）+ 卡片配置 1 个新字段；确认即可实施。
5. 需拍板 **5 项**（§5）。

## 2. 代充卡片样式规范（v2）

### 2.1 信息层级（自上而下）

1. 角标行：左上「主推」徽标（可配）+ 右上「代充」类型标（**新增 ②**）
2. 商品标题（如「ChatGPT Plus 一个月」）
3. 场景副标题（如「日常对话、写作与轻度任务」）
4. 价格行：主价格 + 周期 + 标签（如「官方直充」）
5. **优惠行（新增 ①，启用时显示）**：原价删除线 + 优惠文案
6. 分隔线（虚线）
7. 功能清单（4 条，可配）
8. 保障行 + 时效提示（可配）
9. 主按钮「立即办理 →」
10. 次级入口「购买卡密 · 送朋友 / 先买后用 →」（P1 已有，可关）
11. **底部 chips（新增 ③）**：查看常见问题 / 联系客服 / 批量优惠

### 2.2 三处增补的细化

**① 优惠行（promo）**
- 渲染能力已存在（`kc-cb-promo`），当前配置为空、未显示。
- 显示条件：`promo.strike` 或 `promo.text` 任一非空。
- 样式：原价灰色删除线 + 品牌色文案；推荐文案格式「日常优惠 · 省 $X」。
- 规范：**原价必须真实**（仅使用真实调价前价格，禁止虚构锚点）；默认关闭、后台可配。

**② 类型标**
- 右上角小号软底胶囊「代充」（品牌软底 + 品牌字色）。
- 数据来源：卡片 `category`（现有 `recharge`）。
- 目的：成品号 / 权益上线后共用同一卡面语言（换文案与色调即可）。
- 可现在就上，也可等成品号上线时一并启用（待确认 4）。

**③ 底部服务 chips**
- 三枚轻量胶囊：`查看常见问题`（滚动到页内 FAQ）/ `联系客服`（工单页 `#/ticket`）/ `批量优惠`（工单页）。
- 建议默认开启；文案与链接可配、可整组关闭（新增 `chips[]` 配置字段）。

### 2.3 状态与交互

- 在售（onsale）：常规态。
- 售罄 / 维护（soon）：按钮变「查看开通说明 →」（点击去工单页）——已有，保持。
- 下架：不渲染。
- 悬停（桌面）：卡片轻微上浮、边框转为品牌浅色（统一规格）。
- 移动端：单列、按钮通栏、chips 自动换行。

### 2.4 不做（本次）

- 品牌大色块水印、卡片动效堆砌、档位 Tab。

## 3. 代充流程定义（v1）

### 3.1 两条路径总览

- **路径 A · 立即办理（主路径）**：向导四步，余额支付后自动开通；用户全程看不到卡密。
- **路径 B · 购买卡密（先买后用）**：支付后即时发卡；卡密可囤、可送人、随时兑换。

### 3.2 路径 A 步骤规格

| 步骤 | 用户动作 | 系统行为 | 用户看到什么 | 异常分支 |
|---|---|---|---|---|
| S0 浏览 | 商品页看卡片 | 卡片渲染（价格 / 权益 / 保障） | 完整卡片信息 | 售罄 →「查看开通说明」 |
| S1 进入 | 点「立即办理」 | 登录检查（待确认 7）；已登录直接开向导 | 向导弹层（当前商品信息） | 未登录 → 登录后自动续接 |
| S2 向导① | 点「打开官网」登录 ChatGPT | 打开 chatgpt.com | 图文指引 | 无账号 → 教程引导注册 |
| S3 向导② | 按图文教程获取 Session | 展示复制方法 | 步骤截图 / 说明 | 不会取 → 联系客服 |
| S4 向导③ | 粘贴 Session | 本地解析（邮箱 / 套餐 / 有效期），展示解析结果 | 识别出的账号信息 | 解析失败 → 原因提示、可重试 |
| S5 向导④ | 核对订单并支付 | 余额校验；不足 →「去充值」；**支付前展示购买须知（rules）** | 订单确认：商品 / 目标账号 / 金额 | 余额不足；重复单提示 |
| S6 开通 | （等待） | 提交履约，逐账号串行处理 | 进度条 / 状态 | 失败 → 自动重试 → 补偿队列 |
| S7 完成 | 查看结果 | 订单页留痕 | 「已完成」+ 订单记录 | 长时未完成 → 售后入口 |

### 3.3 路径 B 步骤规格

| 步骤 | 用户动作 | 系统行为 | 异常分支 |
|---|---|---|---|
| T0 浏览 | 点「购买卡密」 | 打开确认弹窗（数量 / 支付 / 说明） | 入口可关（后台配） |
| T1 支付 | USDT 收银台 / 余额支付 | 创建订单 | 支付超时 → 订单保留可续付 |
| T2 收卡 | — | 支付成功自动发卡 | 发卡失败 → 补偿队列 |
| T3 兑换 | 随时到兑卡页提交 Session | 同路径 A 的 S6 履约 | 卡密过期（180 天）/ 已兑换提示 |

### 3.4 状态口径（用户可见）

- 订单：待支付 → 已支付 / 开通中 → 已完成 ｜ 失败 → 补偿中 → 已退款（承诺：失败全额退款）。
- 卡密：待兑换 → 已兑换；有效期 180 天。
- 商品卡：在售 / 售罄维护 / 下架。

### 3.5 异常兜底（对齐参考站承诺）

- 失败：自动重试 → 补偿队列 → 客服 / 工单；卡片与 FAQ 均已承诺「失败全额退款」。
- 资金：余额不足就地充值；支付超时订单保留。
- 重复下单：向导内提示核对（`rules.restrictions` 已有「不要重复创建相同订单」）。
