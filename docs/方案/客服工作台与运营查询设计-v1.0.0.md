## 0. 背景与目标

客服当前查询痛点：信息分散在 **Xboard 用户页 / 订单页 / BEpusdt 钱包后台 / KC 后台** 四处；「用户余额」「订单进度」「充值到账」「卡密状态」需要来回切换、人工比对 —— 慢、易错、口径不一。

本方案：在不触碰 Xboard 内核（红线）的前提下，给客服一个**同源只读工作台**：
**一次输入（邮箱 / 用户ID / 订单号）→ 全部上下文 + 标准话术 + 处理建议**；
所有写操作（补单 / 售后 / 补偿）仍走既有审核流程，客服台不做任何写动作。

## 1. 角色与安全边界

- **使用者**：客服 / 运营（Xboard 管理端登录态）。
- **鉴权模型（2026-10-11 修订）**：页面壳**公开**（不含任何业务数据）；数据接口
  `admin/kc/support/*` 由 `['user','admin']` 中间件保护；壳内 JS 从**同源管理端 localStorage**
  （`VUE_NAIVE_ACCESS_TOKEN`）读取管理员令牌附加到请求头（与内置管理端 SPA 同机制）。
  > 修订原因：`Admin` 中间件只认 `Authorization` 头，浏览器直开页面无头 → 403，无法使用；
  > 运营壳（ops）同步按此模型修订。
- **严格只读**：无改余额 / 改状态接口。补单走 `admin/kc/topups/credit`（必须 TXID + 已核验金额 + 原因）；
  退款走售后工单；补偿走既有 CompensationService。
- **不显示 / 不索要**：密码、Session、支付密钥一律不进任何查询结果；卡密仅供协助用户时查看（页面已注明使用规范）。

## 2. 业务场景（客服视角）

| 场景 | 输入 | 输出与处置 |
|---|---|---|
| **S1 查询用户余额** | 邮箱 / 用户ID | 余额（$）、订阅状态、最近 10 笔订单 / 充值 / 卡密 / 售后 —— 一屏可见 |
| **S2 查询订单进度** | 订单号 | 订单状态 + 发卡状态 + **KC 实时复核**（状态/进度/文案）+ 建议处理 |
| **S3 充值未到账** | 订单号 | 充值台账时间线：未支付（引导付款）→ 已付未到账（要 TXID，走人工补单）→ 异常（人工复核） |
| **S4 卡密 / 兑换问题** | 订单号 | 卡密状态与复制、兑换指引（Session 教程）、失败 → 售后 / 补偿路径 |
| **S5 售后与补偿核对** | 邮箱 / 订单号 | 工单与补偿状态只读呈现，避免重复受理 |
| **S6 标准话术** | —— | 4 张话术卡（Session 指引 / 充值 / 卡密 / 内部边界），一键复制 |

## 3. 接口设计（已实现）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/admin/kc/support/user?q=` | GET | 邮箱 / 用户ID → 用户全景（user / orders / topups / cards / after_sales / compensations） |
| `/admin/kc/support/order?trade_no=` | GET | 订单 + 卡密 + 充值 + 售后 + 补偿 + KC 实时复核 |
| `/plugins/kc_integration/support` | GET | 客服工作台页面（运营壳内链直达） |

约束：全部只读；错误只回通用文案；金额一律按 **$（美元）** 展示。

## 4. 页面与交互

- **查询框自动识别**：含 `@` → 用户查询；≥16 位纯数字 → 订单查询（并互为兜底）。
- **结果分区**：用户卡（余额/状态/订阅）→ 订单表 → 充值表 → 卡密表 → 售后/补偿（有则显示）。
- **订单视图**：订单卡 → 卡密区（大号卡密 + 复制）→ KC 实时复核 → 充值（如为充值单）→ **建议处理**（按状态给出下一步）。
- **话术卡**：常显于页面底部，点击复制全文。

## 5. 处理流程（SOP 摘要）

1. **充值未到账四步**：定位订单 → 核对链上（TXID / 金额 / 网络）→ 补单或复核 → 回访用户。
   - 补单硬要求：订单号 + TXID + 已核验金额；**禁止直接改余额**（走 TopupService 幂等 + 流水）。
2. **开通异常**：先看 KC 实时复核；`failed / expired / frozen` → 引导售后工单 / 补偿（终态失败自动入补偿队列，不重复提交）。
3. **退款**：一律引导工单，客服不直接退款。
4. **言论边界（对内）**：不索取账号密码 / Session / 验证码；不承诺具体时效。

## 6. 验收（2026-10-11 实测）

- **API**：用户全景 / 订单进度均 200，数据正确（订单 `2026101022104201309630610`、卡密 `KC-UEQQHXST39SBBQG`、KC 实时复核取到中文状态）。
- **页面**：标题 / 4 张话术卡 / 两次查询渲染全部通过（证据：`debug_screenshots/support-1/2/3.png`、`support-notes.txt`）。
- **安全**：未登录调数据接口 403；页面壳无任何业务数据；页面与接口输出均无人民币符号/字样。
- **回归**：运营壳（ops）200 且客服入口在位；`tools/check-currency.js` 全绿。
