## 一、现状诊断：问题不在配色，在信息优先级

先看证据（走查截图 `logs/v127-ux/`、`logs/v127-ux2/`）。当前首屏的完整内容顺序是：

```
顶部公告条 → 青绿渐变大 Banner（"ChatGPT Plus / Pro 官方代充"+两个按钮）
→ "两条路径，按你的情况选"（立即代充 / 兑换卡密）→ "选择适合你的套餐" → …
```

四个具体问题：

### 1. 首屏没有价格 —— 而"便宜"正是核心卖点

整屏翻下来**一个价格数字都没有**。用户是冲着"便宜"来的，但页面上看不到任何便宜的证明。价格被压到折叠线以下，还要再滚动一次才出现。

> 结论：最该被放大的信息，位置最边缘。

### 2. "先成为会员 → 享最低价"这条主线完全不可见

你说得很清楚：核心商业模式是**代充便宜，但要先成为会员、升级后享最低价**（本质是 Costco 式会员制批发）。但当前页面上：
- 没有"会员"这个概念
- 没有价格分层（普通价 / 会员价 / 代理价）
- 没有任何"升级能省多少钱"的提示

**用户压根不知道有更便宜的路径 —— 这条主线缺位，等于转换漏斗没了入口。**

### 3. 大面积青绿渐变 Banner 抢走全部焦点

Banner 占据首屏 1/3 高度、满屏饱和青绿，视觉重量远超商品本身。结果是"页面很热闹，但没有重点"—— 人的视线落在色块上，而色块里没有价格、没有商品。

### 4. 全站等权重平铺 + 机场时代术语残留

`Banner → 两条路径 → 套餐 → 底部` 各区块视觉重量几乎相同，没有引导性。同时导航里还留着 `代充 / 成品号 / 建站服务 / 我的订单 / 充值 / 兑换卡密 / 个人中心 / 我的邀请 / 我的工单` 九个入口，术语混用「订阅 / 套餐 / 节点 / 流量」—— 面向"小代理"这类目标客户，噪音太大。

> **一句话诊断**：这不是"配色不好看"，而是**页面没有回答用户唯一关心的问题——"多少钱"**。视觉只是这个问题的表象。

## 二、目标客户与核心叙事

### 目标客户：小代理（月销 10~200 单量级）

画像与真实诉求：

| 他关心 | 他不关心 |
|---|---|
| 拿货价够低，转手有利润 | 平台用了什么技术栈 |
| 能不能一键交付给自己的客户 | 平台的"节点/流量"（他根本不卖这个） |
| 能不能接入 API 自动化 | 平台有多少种套餐排列组合 |
| 站点看起来专业（他要拿去给客户看） | 平台的历史故事 |

### 核心叙事（一句话）

> **「ChatGPT 代充，会员价拿货 —— 自己用便宜，卖给客户更便宜。」**

三层递进，Demo 首页严格按此顺序落地：

1. **便宜**（钩子）→ 首屏就给价格，给对比，给"省多少"
2. **便宜的前提是会员**（转化）→ 会员档位可视化，价格随档位实时变化
3. **会员还能帮你赚钱**（锁定）→ API 接入 + 白标建站，把零售客户升级成长期代理

## 三、⚠️ 开工前必须先定的三件事

这三件事不解决就没法开发，方案里给出我的推荐，**请你拍板**。

### 决策 1（最关键）：平台"会员"在当前系统里怎么落地？

**问题**：现在 Xboard 里的「订阅 / 套餐」= 用户购买的 **ChatGPT 权益**（Plus / Pro）。而你说的"网站会员"= **平台自己的会员等级**。这是两个完全不同的东西，但当前系统里只有前者。

如果直接开做，用户会彻底混淆：*"我买的到底是 ChatGPT 还是你们的会员？"*

三条路径：

| 路径 | 做法 | 改动量 | 我的评价 |
|---|---|---|---|
| **A（推荐）** | 把「平台会员」做成一个特殊商品（如「KC 代理会员 · 年费」），购买后写用户等级字段，全站价格按等级生效 | 小：1 个商品 + 1 个字段 + 价格计算逻辑 | 复用现有下单/支付/发卡链路，最快且不破坏既有逻辑 |
| B | 用 Xboard 用户组 `group_id`，后台手动升级 | 最小，但**必须人工** | 只适合内测期，无法自助转化 |
| C | 新增会员表 + 独立开通流程 | 大：DB + 后台 + 前台三处 | 最干净，但工期长，现阶段不值得 |

> **推荐 A**。理由：你的目标客户是小代理，他们要的是"能自助升级、立刻拿到低价"，B 做不到；C 现在做太重。A 用现有链路就能跑通完整闭环。

### 决策 2：品牌名与对外身份

当前 `KC 加速` 是机场时代遗留（"加速"暗示机场，与"代充"心智冲突，且"加速"二字容易触发合规联想）。

**建议**：对外改用一个中性、批发感的名字（Demo 中暂用 `KC` 标识 + 副标 `GPT 代充 · 代理批发`），实际名称你定。**这条不影响开发，但影响所有文案与 Demo 观感。**

### 决策 3：会员档位数量与命名

推荐三档（Demo 采用）：

| 档位 | 定位 | 定价逻辑（Demo 用的示例值） |
|---|---|---|
| **普通用户** | 零售，未升级 | 标准价 $15 —— **这是锚点，不是真的想卖** |
| **代理会员** | 主推档（标"最多人选"） | 年费 **$199**，享代理价 $9.90 —— **这才是转化目标** |
| **超级代理** | 月流水满 $3,000 自动升级 | $8.50，制造向上动力 |

> 三档的经典作用：中间档是"想要的那个"，右边档是"让你觉得中间档划算"。**不要只做两档**，两档会变成二选一僵局。
>
> **回本叙事是这页的关键**：$199 年费 ÷ 每单省 $5.10 ≈ **卖 20 单回本**。把这句算清楚写在档位上，比任何"低价"形容词都有说服力。数字可按实际成本调整，但**必须让用户自己能算出回本点**。

## 四、信息架构：从 9 个入口砍到 3 + 1

**现状 9 个导航入口 → 新方案 3 主入口 + 1 工具位**

| 新导航 | 职责 | 吸收的旧入口 |
|---|---|---|
| **首页** | 价值主张 + 价格钩子 + 三步流程 | 原首页 |
| **价格** | 全部商品 × 会员档位价目矩阵 | 代充、成品号、套餐列表 |
| **代理** | API 接入 + 白标建站（目标客户主场景） | 建站服务、我的邀请 |
| 右上角**余额 / 订单** | 极简工具区，不占主导航 | 我的订单、充值、个人中心、我的工单 |

**砍掉的处理方式**：
- `兑换卡密` → 从主导航移到订单页顶部的一个次级入口（"已有卡密？"）
- `我的邀请` → 并入「代理」页
- `我的工单` → 并入订单页底部入口

> 原则：**主导航只留用户"主动想去做的事"，工具类入口一律收进右上角。**

## 五、视觉系统

### 5.1 两套配色（Demo 可实时切换对比）

#### 方案 A · 墨黑 + 省钱绿（**推荐**）

| 角色 | 色值 | 用途 |
|---|---|---|
| 主色 Ink | `#0E1116` | 标题、主按钮、导航 —— 近黑，克制、专业 |
| 省钱绿 Save | `#00A862` | **只用于价格数字与省钱金额**，绝不滥用 |
| 背景 | `#FFFFFF` / `#F6F7F9` | 大面积留白 |
| 分割线 | `#E8EAEE` | 极细，0.5px 观感 |
| 次要文字 | `#5A6270` | |

**为什么推荐**：目标客户是要**拿去卖给客户**的小代理 —— 站点越像专业的现代 SaaS（Stripe / Vercel 那种气质），他越好卖。近黑主色把"高级感"和"克制"做足，绿色只出现在价格上，形成**全页唯一的视觉焦点 = 钱**。

#### 方案 B · 深蓝 + 促销橙

| 角色 | 色值 | 用途 |
|---|---|---|
| 主色 | `#0B1220` | 深蓝黑 |
| 促销色 | `#FF5A1F` | 价格、CTA、"便宜"信号 |

**气质差异**：更电商、促销感更强、压迫感也更重。转化可能更猛，但"廉价感"风险更高 —— 小代理拿它给客户看时，客户容易觉得"这站不靠谱"。

> **我的建议：A 做正式版，B 可以留着做活动页。** 两套在 Demo 里都能切，你自己看感受。

### 5.2 排版规则（极简的关键在执行）

这几条是"极简"和"简陋"的分界线，必须遵守：

1. **价格是页面上字号最大的元素** —— 会员价 64px，原价 16px 划线。层级差距要夸张。
2. **数字用等宽数字**（`font-variant-numeric: tabular-nums`），价格对齐、有精密感。
3. **留白翻倍** —— 区块间距至少 96px，卡片内边距 24~32px。宁可空，不要挤。
4. **删掉一切装饰性渐变** —— 全站零渐变、零阴影滥用；卡片只用 1px 描边区分层级。
5. **去掉所有图标堆砌** —— 全站图标不超过 6 个，且只用线条型。
6. **一屏一个决定点** —— 每个屏幕只允许一个主按钮（实心），其余一律文字按钮。

### 5.3 术语表（必须统一，开发时逐字对照）

| 旧（Xboard 术语） | 新（对客户说） |
|---|---|
| 订阅 / 套餐 / 计划 | **账号 / 商品** |
| 节点 / 流量 / 重置 | **删除**（与本业务无关） |
| 服务周期 30 天 | **有效期 30 天** |
| 代充开通 / 兑卡 | **发卡 / 开通** |
| 余额充值 | **账户余额** |
| 立即订阅 | **立即购买** |

## 六、核心页面结构与转化逻辑

### 6.1 首页（Demo 重点，六个区块）

```
┌ ① Hero：左主张 + 右价格卡 ────────────────────────┐
│  左：H1 "会员价拿货"  + 一句副标 + 主CTA           │
│  右：价格对比卡（原价划线 / 会员价绿色大字 / 省34%）│
│  ← 首屏必须出现价格，这是整个改版最核心的一处改动   │
├ ② 会员档位条（三档，中间档高亮"最多人选"）────────┤
├ ③ 商品网格（每张卡：会员价大字 + 原价划线 + 一键购买）┤
├ ④ 三步拿到账号（注册 → 升级会员 → 下单拿卡）──────┤
├ ⑤ 给小代理：API 接入 / 白标建站（两个入口卡）─────┤
└ ⑥ 信任条（自动发卡 · 3分钟到账 · 失败必退 · 售后响应）┘
```

### 6.2 首页的关键交互：**会员档位切换 → 价格实时联动**

这是整个 Demo 里最重要的一个交互，也是你商业模式的直接翻译：

> 页面上放三个档位 Tab（普通 / 代理会员 / 超级代理）。用户点一下，**下面所有商品价格立刻跟着变**。
>
> 用户不需要读任何说明文字，**只要点两下就能亲眼看到"升级能省多少钱"** —— 这比任何文案都有说服力。

这个组件承担了整个转化漏斗的主要压力。

### 6.3 价格页

一张**档位 × 商品**的价目矩阵（不是三张卡片横向排列）。用户一眼扫完自己所有选项，且每一列都是"比上一列便宜"，天然制造升级动机。

### 6.4 代理页（面向目标客户的核心页）

- **API 接入**：三步（拿密钥 → 调下单接口 → 收卡密），配一段可复制的 curl
- **白标建站**：一句价值主张 + 需要什么（你要的只是流量）
- 两个入口都要明确写出**"你能赚多少"**的计算示例，而不是罗列功能

### 6.5 订单页（极简）

单列列表，每行只有：商品 / 金额 / 状态 / **一键复制卡密**。不跳页、不折叠、不需要二次确认。

## 七、交互极简六原则

写给后续实现者，也作为验收标准：

1. **3 秒原则** —— 任何页面打开 3 秒内，用户能回答"我要花多少钱、能得到什么"。
2. **价格优先原则** —— 价格永远是页面上字号最大、对比度最高的元素。
3. **单决定点原则** —— 一屏只有一个实心主按钮，其余为文字按钮或次级样式。
4. **零术语原则** —— 用户不需要理解你的系统才能买东西。
5. **默认路径唯一原则** —— 新访客只有一条路：看价 → 升级会员 → 下单。不要给他"两条路径按你的情况选"（那是设计者的思路，不是用户的）。
6. **少一次跳转原则** —— 能就地展开的不要跳页；卡密一律就地复制。

> 第 5 条是对现状最直接的否定：当前首页那个「两条路径，按你的情况选」区块，**要求用户先理解系统（买 vs 兑换的区别）才能行动**，成本和收益不成比例，新方案移除。

## 十、Demo 说明

文件：`design/前台改版demo-v1.0.0.html`（单 HTML，无外部依赖，双击打开）

**能看什么**：
1. 四个页面：首页 / 价格 / 代理 / 订单
2. **两套配色实时切换**（右上角"配色"按钮）—— 用来对比方案 A 与 B
3. **会员档位切换，价格联动** —— 首页第 ③ 区块，点 Tab 看价格变化
4. 移动端自适应（拉窄窗口即可看）

**Demo 不是什么**：纯静态原型，不接后端、不写入任何系统，仅用于评审视觉与交互方向。
