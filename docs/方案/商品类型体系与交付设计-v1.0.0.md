# 商品类型体系与交付设计（代充 · 成品号 · 权益）

> 方案编号：`SP-2026-10-11-v1.0.0`　文档状态：**待用户审核**
>
> 来源：2026-10-11 用户提出三类商品需求——① 代充商品（走前台 GPT 代充流程）；② 成品号商品（预约 / 账号池自动发货，交付账号、密码等字段且字段可配置）；③ 权益（购买后开通，可以以不同于平台报价的价格购买代充或成品号商品）。
> 基线：`v1.13.0`；载体：Xboard 商城（当前唯一在售入口）；落点遵守《后台形态选型》（已确认）：运营层自建、内核借壳少改，Xboard 侧只走「插件 API + 壳层」两类允许改动。
> 本方案只定产品功能与交互 + 必要的系统调整点，不含开发。审核通过后按 §10 分期执行（每段停下再确认）。

---

## 0. 一页结论

1. 三类商品 = 三套**交付模型**：代充 = 服务履约（现有）、成品号 = 库存履约（新增）、权益 = 价格权益（新增）。购买骨架统一（选品 → 支付 → 交付 → 售后），差异全部收口在「交付层」与「价格层」。
2. 成品号的两个关键机制：**下单先锁号**（预占 30 分钟自动释放，可配）杜绝"付了没货"；**无货可预约**（付款排队、按序发货、未发货随时退）。
3. 权益的关键机制：**自动最优价**——下单时系统自动套用最优权益价，用户不用输码、不用做选择。
4. 前台统一语言：三色类型标（代充·蓝 / 成品号·绿 / 权益·金），每张卡一眼看懂"交付什么、多久拿到、怎么售后"。
5. 全部落在插件 API + 运营壳页面，不动 Xboard 内核；客服工作台同步扩展。
6. 待拍板 7 项（§11）；其中 1 项涉及红线扩展：成品号库存凭据需「加密落库 + 访问审计」（与"用户授权信息不落库"红线不冲突，属新增库存资产）。

## 1. 设计原则（用户体验优先）

- **一眼可辨**：类型差异在卡面讲清，不用点进详情。
- **最短路径**：现货成品号 = 付款到拿号 ≤ 1 分钟；权益价自动生效。
- **确定性**：库存预占防超卖；预约有位次、有预计时间、可退；权益剩余次数 / 有效期透明。
- **购前说清**：能退 / 不能退、售后窗口、限购，都在付款前给到。
- **容错**：冲突与异常都有兜底路径（§4.2 / §5.4），资金安全第一。

## 2. 商品体系总览

| 类型 | 一句话 | 交付方式 | 价格逻辑 | 售后口径 |
|---|---|---|---|---|
| **代充商品** | 帮用户的 ChatGPT 账号开好订阅 | 向导现场办 / 卡密后办（现有双入口） | 标价；可享权益价 | 失败补偿队列（现有） |
| **成品号商品** | 直接把一个可用账号交给用户 | 现货自动发货 / 无货预约 | 标价；可享权益价 | 限时换号 / 退款（审核） |
| **权益商品** | 把「专属价资格」卖给用户 | 支付后即时开通（账户权益） | 本身有价；作用于目标商品产生「权益价」 | 开通后不可退（购前明示） |

- **类型标记**：商品增加类型字段（如 `kc_type: recharge / account / entitlement`），前台卡面三色标识。
- **与现有机制的关系**：代充现状保留（向导 + 卡密）；成品号与「卡密」的区别 = 交付物不同（账号本体 vs 兑换码）；权益可作用于代充与成品号（含各类购买路径）。

## 3. 类型一 · 代充商品（承袭 + 增量）

现状（向导、卡密、订单进度、补偿队列）全部保留。增量三点：

1. 卡面挂类型标（蓝色「代充」），与两类新商品语言统一；
2. 支持权益价（权益体系的受益对象之一）；
3. （建议）与《卡密购买模式》P2 联动：把「我的卡密」扩展为「我的资产」（卡密 + 成品号 + 权益 一页聚合，一次做）。

## 4. 类型二 · 成品号商品

### 4.1 前台交互

- **商品卡**：绿色「成品号」标；标题 = 商品名（如 "ChatGPT Plus 成品号"）；交付承诺一行（"付款后自动发放：账号 + 密码"）；库存语义——`现货 N`（>10 显示"库存充足"）/ `仅剩 N 件`（1–10）/ `可预约`（0 且开启预约）/ `暂时售罄`（0 且未开预约）；限购提示（每人 N 件）；CTA：现货 = 「立即购买」，无货 = 「预约购买」，未开放 = 「到货通知」。
- **购买确认弹窗**：商品摘要 + **交付字段清单预览**（"你将收到：账号 / 密码 / 辅助邮箱"）+ 限购 + 支付方式（USDT / 余额）+ 购前须知（售后窗口、预约退款规则）。
- **支付完成（现货）**：订单页出现「**交付卡**」——字段逐项展示：单条复制；密码默认打码、点击显示；大按钮「复制全部」（生成格式化文本，便于存档）；附操作指引（"请尽快修改密码并绑定自己的邮箱"）。订单页是唯一入口，可随时回看。
- **支付完成（预约）**：订单显示"预约中 · 第 N 位 · 预计 X 天"；按钮「取消预约（全额退至余额）」；到货发货后自动转为交付卡 + 站内提醒。
- **售后入口**：订单页「账号有问题？」→ 换号 / 退款申请（窗口内），进度可查。

### 4.2 发货机制（防"付了没货"）

1. **下单即锁号**：预占 1 条库存（支付窗口 30 分钟，超时自动释放；时长可配）；
2. 支付成功 → 预占转「已交付」（幂等：重复回调不重复发放）；
3. **兜底**：支付到账时若预占已过期且无货 → 自动进入「优先队列第 1 位」（视同最高优先预约）+ 站内通知 + 可一键退；
4. 预约单：付款后按序排队（FIFO），到货自动发货；**未发货可随时取消、全额退**；
5. 交付系统异常 → 自动重试 + 失败进补偿队列，客服台可见。

### 4.3 交付字段（可配置）

- **字段模板编辑器**（商品级）：字段名 / 类型（文本、密码、链接、长文本）/ 默认打码 / 是否必填 / 提示文案 / 排序；内置预设（ChatGPT 成品号：账号、密码、辅助邮箱、2FA 密钥、使用说明）。
- **库存导入**：单条录入 + CSV 批量导入（列 ↔ 字段映射、重复与必填校验、导入报告）。
- **顾客侧规则**：仅展示「顾客可见」字段；打码字段点击显示；每次查看写日志（争议时溯源）。

### 4.4 后台功能

- **商品配置页**（运营壳）：类型 = 成品号；交付方式（现货自动 / 可预约）；限购；低库存预警阈值；预计补货文案。
- **库存管理页**（新）：列表（可用 / 已预占 / 已交付 / 作废 / 异常）+ 搜索 + 单条编辑 + 作废 + 批量导入；统计卡（总量 / 可用 / 今日消耗）；低库存预警（运营通知）。
- **订单侧操作**：交付记录、重新展示、换号（旧号作废 → 分配新号，全程记录）、退款协助（转售后流程）。
- **客服工作台**：按订单 / 用户查交付状态与字段（打码 + 授权查看 + 审计）；话术卡新增「成品号换号 / 退款口径」。

### 4.5 售后口径（建议默认值，可调）

- 交付后 24 小时内、首次登录失败 / 凭据无效 → 免费换号 1 次 或 退款（客服审核 + 凭证）；
- 超窗、已改密、或非凭据问题 → 不换不退；
- 一切处理写入订单时间线。

### 4.6 安全设计（红线配套）

- 凭据**加密落库**（AES-256-GCM，密钥在环境变量，不进代码 / 日志）；展示端按需解密、默认打码；
- 所有「查看明文」动作**审计**（谁 / 何时 / 哪条）；导出与批量操作单独授权；
- 红线修订建议：原「用户授权信息不落库」保持不变；**新增一条**——「成品号库存凭据属受控资产：加密存储、默认打码、访问审计」。

## 5. 类型三 · 权益商品

### 5.1 概念模型

权益 = 一条「规则包」：**适用商品**（多选：代充 / 成品号）+ 每个目标的**权益价** + **有效期**（天）+ **使用限制**（总次数 / 每周期次数 / 每人限购）+ 生效方式（支付成功即生效）。

### 5.2 前台交互

- **权益商品卡**：金色「权益」标；价值直给（示例："Plus 代充 $15 → $10"）；CTA「立即开通」。
- **权益详情**：适用商品与权益价一览表、有效期、次数、规则、常见问题。
- **生效呈现**：已开通用户的适用商品卡自动显示「**权益价 $X**」（原价 $Y 划线）+ "权益已生效"小标；未开通用户看到"开通权益可享 $X"（一键直达权益商品 —— 引流闭环）。
- **结算**：金额行显示"权益价（原 $Y）"；无需输码、不用选择；多权益重叠自动取最优、不叠加其他优惠。
- **用户中心「我的权益」**：生效中 / 已过期分组；剩余次数、到期倒计时、使用记录、「去使用」入口；到期前 7 天站内提醒。

### 5.3 后台功能

- **权益配置页**：规则编辑器（目标商品多选、逐项权益价（必须 < 原价）、有效期、次数、限购）；上 / 下架。
- **数据**：开通记录、使用记录（关联订单）、转化统计；冻结 / 撤销（需原因 + 审计）。
- **价格保护**：权益价 ≥ 原价不允许保存；低于成本价给警告。

### 5.4 资金与退款口径

- 权益价订单走现有支付通道（余额 / USDT）；订单记录「原价 / 权益价 / 权益引用」；
- 订单未交付退款时：权益次数回补；
- 权益商品本身：开通后不可退（购前明示）。

## 6. 统一体验（跨三类）

- **卡面语言统一**：三色类型标 + 交付承诺一行 + 价格区 + CTA；三类商品在同页混排（可加筛选），不拆多页。
- **交付统一**：「订单 → 交付卡」，用户只需记住订单页。
- **售后统一**：订单页「需要帮助」入口；三类口径购前说清。
- **通知**：状态变化订单页可见（一期）；邮件 / Telegram 提醒（二期可选）。
- **资产聚合（建议）**：「我的资产」= 卡密 + 成品号 + 权益（与卡密 P2 合并做）。

## 8. 系统调整点（现状 → 目标）

1. **类型标记**：`kc_type: recharge | account | entitlement`（侧表或配置存储，由 `/plan/kc-cards` 带出）。
2. **价格层**：新增「定向价下单」能力（权益价订单、预约单金额）——不动原生定价。
3. **履约钩子**：新增「成品号交付」链路（支付成功 → 锁号兑现），幂等（唯一键 + `INSERT IGNORE` 沿用）。
4. **库存预占与释放**：预占窗口 + 超时惰性清理。
5. **新增数据（插件侧）**：账号库存、字段模板、权益规则、权益持有、使用记录、交付日志（命名沿用插件约定）。
6. **前台注入**：商品卡三态渲染、交付卡、我的权益 / 资产页。
7. **客服台**：三类查询扩展。
8. **安全**：凭据加密组件 + 审计日志。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 凭据安全（库存账号） | 加密 + 默认打码 + 访问审计；导出单独授权 |
| 预约占座与资金占用 | 条款明示（未发货可退、退至余额秒到）；异常预占自动释放 |
| 权益滥用 / 低价转卖 | 限购 + 次数限制 + 异常行为冻结 |
| 并发一致性（锁号 / 交付） | 预占事务 + 唯一键；交付幂等；回调重复不重复发放 |
| 账号业务争议 | 不承诺"永久可用"；售后窗口 + 凭证流程；处理留痕 |
| 复杂度膨胀 | 分期落地，每期独立可用；守三类允许改动 |

## 10. 分期路线（建议；每段停下确认）

- **P1 · 成品号（现货自动发货）**：字段模板 + 库存池 + 预占 + 交付卡 + 库存管理页 + 客服台扩展 → 目标：可开卖。
- **P2 · 预约 + 售后闭环**：预约排队 / 取消退款、换号 / 退款流程、低库存预警、通知。
- **P3 · 权益体系**：规则配置 + 权益价生效（代充 & 成品号）+ 我的权益 + 使用审计。

> 顺序可调；若权益急用可提前，但建议先以成品号练通「库存履约」。

## 11. 待拍板（审核要点）

1. **命名**：「成品号 / 权益」就用这两个词？三色标（代充蓝 / 成品号绿 / 权益金）？
2. **预约形态**：建议「付款排队 + 未发货随时退」、预占窗口 30 分钟；若你要「到货通知（不付款）」或「指定发货时间」，请说。
3. **售后窗口**：建议 24h / 换号 1 次；窗口与次数按你的口径调。
4. **权益解读**：按「专属价购买权」设计（适用代充 + 成品号）；是否还需要「权益解锁非公开商品」？
5. **红线扩展**：接受「成品号库存凭据加密落库 + 审计」新增条款？
6. **交付字段回看**：建议允许回看 + 日志（可随时收紧为限次）。
7. **分期顺序**：P1 成品号 → P2 预约售后 → P3 权益，认可？
