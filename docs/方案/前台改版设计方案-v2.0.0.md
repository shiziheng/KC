## 一、模型定义（先把规则说准）

你说的不是"会员等级"，而是**预购折扣次数**。规则如下：

```
买权益包  →  获得 N 次「低价购买权」
每次下单  →  可选择消耗 1 次，按权益价结算
次数用完  →  恢复原价购买
包按月订阅，次数按周期刷新
```

这个模型有个很重要的性质：**它不是身份，是额度**。用户不需要"升级"，他只需要"买次数"。所以界面语言里**不应该出现"等级、升级、会员"** —— 这些词会让用户以为是身份系统，而实际要传达的是"你手上还有几次便宜机会"。

### 当前规则参数（来自你的说明）

**权益包（两类）**

| 包 | 价格 | 含权益次数 | 每次机会成本 |
|---|---|---|---|
| 轻享包 | $15 / 月 | 5 次 | **$3.00** |
| 畅享包 | $99 / 月 | 50 次 | **$1.98** |
| 建站支持套餐 | $399（周期待确认） | API + 建站支持 + 维护（是否含次数待确认） | — |

**商品（原价 vs 权益价）**

| 商品 | 原价 | 权益价 | 每次省 |
|---|---|---|---|
| ChatGPT Plus | $18.00 | $16.50 | **$1.50** |
| ChatGPT Pro 100 | $98.00 | $93.00 | **$5.00** |
| ChatGPT Pro 200 | $155.00 | $145.00 | **$10.00** |

## 二、⚠️ 我把账算了，有一个问题必须先告诉你

这是设计前必须确认的，因为**它直接决定界面上怎么推荐用户用这个包**。

### 核心矛盾：Plus 用权益是亏的

| 商品 | 每次省 | 轻享包每次成本 $3.00 | 畅享包每次成本 $1.98 |
|---|---|---|---|
| Plus | $1.50 | **亏 $1.50** ✗ | **亏 $0.48** ✗ |
| Pro 100 | $5.00 | 赚 $2.00 ✓ | 赚 $3.02 ✓ |
| Pro 200 | $10.00 | 赚 $7.00 ✓ | 赚 $8.02 ✓ |

**结论：Plus 的折扣（$1.50）低于权益次数本身的成本（$1.98~$3.00），用户把机会用在 Plus 上是纯亏。**

这带来两个后果：
1. 用户如果主要买 Plus，他会觉得这个包是骗人的 —— **口碑风险**。
2. 界面如果无差别地推荐权益包，等于在引导用户做亏本交易。

**三个解法，请你选一个：**

| 方案 | 做法 | 说明 |
|---|---|---|
| **① 抬高 Plus 折扣（推荐）** | Plus 权益价压到 **$15.00 或更低**（省 $3+） | 让所有商品用权益都不亏，逻辑最干净 |
| ② 保持现状 + 界面强提示 | 界面明确标注"建议把权益用在 Pro 系列" | 诚实，但用户会问"那 Plus 为什么要给权益价" |
| ③ 把权益次数改成"定向" | 只对 Pro 系列生效，Plus 不参与 | 规则变复杂，但不用调价 |

我推荐 ①。**理由**：这个包的核心卖点是"5 次机会换更大的省钱空间"，一旦出现"用权益反而亏"的情况，整个包的信任就崩了。Plus 是你的流量款，恰恰是用户最先接触的商品，不能让他在第一个商品上就发现不划算。

### 回本点（设计上要直接告诉用户）

| 包 | 回本需要 | 最优用法（全买 Pro 200） |
|---|---|---|
| 轻享包 $15 | 3 次 Pro 100 **或** 2 次 Pro 200 | 省 $50，**净赚 $35** |
| 畅享包 $99 | 20 次 Pro 100 **或** 10 次 Pro 200 | 省 $500，**净赚 $401** |

> **这是我建议在界面上直接放出来的数字。** 用户不需要自己算 —— 页面帮他算好，他只需要判断"我一个月能不能卖出去 2 个 Pro 200"。这个判断门槛极低。

## 三、命名与语言系统

这个模型最怕用户误解成"会员等级"。语言必须精确：

| 概念 | 界面用语 | ❌ 不要用 |
|---|---|---|
| 权益包 | **低价权益包** / 权益包 | 会员、VIP、等级、套餐 |
| 单次机会 | **1 次低价购买权** / 简称"1 次权益" | 积分、点数、额度 |
| 剩余次数 | **剩余 3 / 5 次** | 等级进度、成长值 |
| 使用动作 | **用权益购买**（消耗 1 次） | 兑换、抵扣、升级 |
| 次数耗尽 | **权益已用完，按原价购买** | 降级、过期 |
| 商品价格 | **原价** vs **权益价** | 划线价、活动价 |

**核心句式**（全站统一）：
> 「用 1 次权益，省 $10」

一句话同时说清"消耗什么、得到什么"。所有按钮、提示、订单记录都用这个句式。

## 四、信息架构

在 v1.0.0 的三主入口基础上，增加一个**权益包**主入口（它是商业模式的核心，必须一级可见）：

| 导航 | 职责 |
|---|---|
| **首页** | 权益包价值主张 + 商品双价 + 使用流程 |
| **权益包** | 三档对比 + 收益计算器 + 常见问题 |
| **价格** | 原价 / 权益价完整对照 |
| **代理** | API 接入 + 建站支持套餐（$399） |
| 右上角 | **权益状态（剩余次数）** + 余额 + 订单 |

> **右上角必须常驻显示"剩余 X / Y 次"**。因为次数是这个模式里唯一需要用户时刻感知的资源 —— 没次数了就得买，有次数就该用掉。它是转化触发器。

## 五、核心界面设计（四个关键组件）

### 5.1 次数点阵 —— 这个模式天然的视觉语言

"5 次权益"最直观的表达不是文字，是**5 个点**：

```
剩余权益    ● ● ● ○ ○   3 / 5 次
```

- 实心 = 可用，空心 = 已用
- 用在：右上角状态、权益包卡、订单页、下单确认
- 为什么有效：**用户一眼就知道"我还剩几次"**，不需要读数字。次数见底时（●●○○○ → ○○○○○）会产生自然的补货冲动。

这是整个改版里最值得投入的一个组件。

### 5.2 双价商品卡

每张商品卡同时呈现两个价格，且**明确标注消耗**：

```
┌────────────────────────────┐
│ ChatGPT Pro 200            │
│ 有效期 30 天                │
│                            │
│  $145.00        ← 权益价（绿）│
│  用 1 次权益 · 省 $10       │
│  ─────────────────         │
│  原价 $155.00              │
│                            │
│  [ 用权益购买 ]             │
└────────────────────────────┘
```

**三种用户状态下按钮不同**（这是状态设计，Demo 里可切换查看）：

| 状态 | 价格显示 | 按钮 |
|---|---|---|
| 无权益包 | 只显示原价 + 权益价对照 | 「买权益包 · $15 起」 |
| 有次数 | 权益价大字 + 剩余次数 | 「用权益购买」（消耗 1 次） |
| 次数用完 | 原价大字 + 灰色提示 | 「原价购买」+ 次级「补权益包」 |

> 极简原则：**不要在下单时弹窗问"用不用权益"**。有次数就默认用，把选择权交给"买不买包"，而不是"每次都要决策一次"。

### 5.3 收益计算器（权益包页）

这个模式的"证明器"。用户加减数量，实时看到省多少、净赚多少：

```
你打算这个月买几次？
Plus        [−] 0 [+]
Pro 100     [−] 1 [+]
Pro 200     [−] 2 [+]
────────────────────────────
用掉权益        3 / 5 次
共省            $25.00
权益包成本       $15.00
────────────────────────────
净收益         +$10.00   ✓
```

- 次数用超了 → 提示"超出 1 次，将按原价购买"
- 净收益为负 → 明确显示亏损（**不要隐藏，否则重演"用户觉得自己被骗"的问题**）
- 这是把"值不值"从用户脑子里搬到屏幕上的组件

### 5.4 三档产品对比（权益包页）

两类产品放在同一页但**分组呈现**，因为性质不同：

- **折扣权益包**（$15 / $99）：买次数，省钱用
- **建站支持套餐**（$399）：买能力，用来做生意

不要混在一个表格里，否则用户会拿"次数"和"API 权限"做比较 —— 它们不可比。

## 六、首页结构（改版重点）

```
① Hero：左主张 + 右权益包卡
   左：H1「花 $15，买 5 次低价拿货权」
       副标：Pro 200 原价 $155，用权益 $145。5 次全用，省 $50。
       CTA：查看权益包 / 已有权益？登录
   右：权益包卡 —— $15/月 + ●●●●● 次数点阵
       + 三个商品各能省多少（一行一个）
       + 底部结论：「全买 Pro 200 可省 $50，净赚 $35」

② 权益怎么用（三步，必须含"用完恢复原价"）
   ① 买权益包 → ② 用权益价下单（消耗 1 次）→ ③ 次数用完，按原价购买
   ⚠️ 第③步必须显著，这是最重要的预期管理

③ 商品（双价卡片，三张）

④ 权益包对比（轻享 $15 / 畅享 $99 / 建站 $399）

⑤ 给小代理（API 接入 + 建站支持）

⑥ 信任条
```

**Hero 的关键取舍**：首屏不出现"原价 $18"这种弱信息，而是**直接给出"能省多少"的结论数字**。因为目标用户（小代理）做的是生意决策，他关心的是净收益，不是单价。

## 七、必须处理的三个边界情况

设计时容易漏，但都会真实发生：

1. **次数跨周期**：包按月，次数当月不用完是否结转？**建议不结转**（否则用户会攒次数，收入不稳定），但界面上必须写清楚，且**在月底给提醒**。
2. **权益订单的退款**：用权益价买的单如果退款，**消耗的次数要不要退**？建议退次数不退包费，并在订单详情写明。
3. **次数刚好用尽的瞬间**：用户下单时是第 5 次，成功后应该立刻有一条明确反馈（"本次已使用最后一次权益，后续将按原价"）—— 这是自然的补货提醒时机，别浪费。
