# 代充独立后台功能重建计划（低成本方案）

> 计划编号：`DP-2026-10-07-v1.0.0`  
> 文档状态：**低成本重建方案，待用户审核**  
> 产品方案基线：`BP-2026-10-07-v1.0.0`（已确认，仍有效）

## 重要说明

本文件不是原计划文件或已丢失代码的恢复件。此前把 ARC-001 至 MIG-016 标为完成的记录已撤销，**本文件所有开发任务均为待审核/待实施**。数据库中曾记录的迁移状态未经本次核实，任何写库和部署操作都要等本计划审核后进行。

本计划只列功能与交付顺序，不表示任何功能已经实现。任务开始前应逐项按批准范围落地并以实际代码、只读/模拟验证记录验收。ZovoCard 必须保持 Mock，禁止真实扣款、真实代充履约和真实生产支付。

## 交付原则

- 独立后台是面向运营、客服、财务的业务入口；KC 技术后台的菜单保持原样，不做菜单迁移或删改。
- 先形成一套运营可理解的业务菜单和入口；可以暂不做技术系统合并，但不应让运营人员在业务菜单层级混用 KC 与 Xboard 的技术菜单。
- Session、Token、Cookie、密码、卡号等敏感凭据不得保存；只记录经批准的关键账户信息和脱敏摘要。
- 订单、支付、履约、余额、售后状态分离；余额相关变更必须可追溯、幂等、可复核。
- USDT 充值使用可识别订单的随机金额尾数/识别码设计；异常到账提供人工核验与受控补单方案。补单只能记录链上凭证并修复平台账务，不得导致平台余额无审计地直接改写。
- 优惠券/活动、在线客服按低优先级处理；分销相关暂不做；不开发发票，只提供交易凭证。
- 外部真实支付、生产钱包接入、真实履约和灰度切换均不在本轮实现范围内，另行审批。

## 低成本实现策略（以核查结果为准）

本次只核对了代码/文档，不检查运行中的数据库，不修改任何系统。当前可以确认的复用点：

- Node/Express 主服务、现有后台登录与鉴权代码仍在；优先在同一服务增加独立业务路由，不另建 API 服务、容器或登录体系。
- `public/admin.html` 是现有 KC 技术后台页面。只复用视觉样式或通用组件，不改它的菜单和现有功能；新业务控制台用单独入口、单独的业务菜单。
- `web/` 下已有 Next.js 用户页面框架，但现有 API 封装代理到 Xboard。先保留页面和布局，只为已确认的代充路径新增业务 API 适配；逐页迁移，不整体重写前台。
- `tools/xboard-patches/KcIntegration/` 有部分代充插件、流水、售后和风险控制的参考代码。仅做逐项代码审查后择取可复用逻辑，不直接假设已部署、不复制整个插件，也不依赖 Xboard 菜单才能运行。
- 业务数据优先使用同一 MySQL 服务中的独立业务库/表空间，避免增加数据库服务；只有在 REC-000 只读核实确认隔离条件、账号权限和现存数据后，才确定复用或新建。不得直接写 KC/Xboard 旧业务表。
- 不做旧测试数据兼容和历史业务数据迁移；只支持新业务结构及必要的模拟数据。运行库现状没确认前不执行迁移。

因此最小架构为：**一个现有 Node 服务 + 独立业务路由/存储 + 一个独立业务后台页面 + 逐步适配现有 Next.js 页面**。KC 后台保持原样；Xboard 仅隐藏/收起非代充菜单入口，不删除其代码、数据和路由，确保能回退。

| R3 · 用户端最小接入 | WEB-015 | 复用 Next.js 登录、导航、样式和现有页面结构；只替换代充需要的商品、下单、订单状态和凭证 API；保留旧 Xboard 页面/接口作为回退，不做全站重写 | 中 | 用户可查看商品、创建模拟订单、看到支付/履约状态；授权信息不落库、不进日志 |
| R4 · 运营收尾 | OPS-009、AFS-010、FIN-011 | 增加异常队列、最小售后状态、交易凭证；用户支持先提供人工联系/留言入口，不上实时聊天系统 | 小至中 | 异常有待办及处理记录；凭证明确非发票；不调用真实退款 |

**低成本下的首个可交付版本只做到 R0–R2**：后台统一业务入口与业务菜单、收起 Xboard 非代充菜单入口、代充商品配置、订单查询、USDT 随机识别与余额异常补单。R3–R5 作为后续批次，避免第一版同时重写前台、整合两套后台和迁移历史数据。

## 暂不纳入本期

- KC 后台菜单改造或迁移：不做，保持现状。
- Xboard 机场相关无关功能：不迁移到独立业务后台；允许本期收起其菜单入口，但不删除原功能、数据和路由。
- 分销、分销提现与推广看板：暂不开发。
- 发票：不做；交易凭证不等于发票。
- 优惠券/活动、在线客服：最低优先级，当前只保证不阻塞网站整体使用；在线客服后续可按人工接待体验补充方案。
- 启用 KC 自有代充能力、面向下游开放 API/独立站：仅作远期记录，不排入本期。
- 任何真实扣款、生产钱包收款、真实供应商履约：不做。
