# 代充独立后台功能重建计划（低成本方案）

> 计划编号：`DP-2026-10-07-v1.0.0`  
> 文档状态：**已审核；R0–R2 代码已实施，部署与菜单接入待完成**
> 产品方案基线：`BP-2026-10-07-v1.0.0`（已确认，仍有效）

## 重要说明

本文件不是原计划文件或已丢失代码的恢复件。用户已批准按低成本 R0–R2 执行。本次只读核验确认 `kc_business` 已有 `0001`、`0002` 两项迁移和业务记录；因此直接适配现存结构，不执行迁移、不清空/造数。R0 已完成；R1/R2 代码已实现但尚未部署。Xboard 的统一菜单跳转因运营可访问地址和登录衔接尚未明确，暂不写入 Xboard 工作区。

本计划同时记录实施结果和后续交付边界。代码就绪不等于已部署或可供运营使用，只有经过运行时部署和入口验收才可标记为交付。ZovoCard 必须保持 Mock，禁止真实扣款、真实代充履约和真实生产支付。

## 交付原则

- 独立后台是面向运营、客服、财务的业务入口；KC 技术后台的菜单保持原样，不做菜单迁移或删改。
- 先形成一套运营可理解的业务菜单和入口；可以暂不做技术系统合并，但不应让运营人员在业务菜单层级混用 KC 与 Xboard 的技术菜单。
- Session、Token、Cookie、密码、卡号等敏感凭据不得保存；只记录经批准的关键账户信息和脱敏摘要。
- 订单、支付、履约、余额、售后状态分离；余额相关变更必须可追溯、幂等、可复核。
- USDT 充值使用可识别订单的随机金额尾数/识别码设计；异常到账提供人工核验与受控补单方案。补单只能记录链上凭证并修复平台账务，不得导致平台余额无审计地直接改写。
- 优惠券/活动、在线客服按低优先级处理；分销相关暂不做；不开发发票，只提供交易凭证。
- 外部真实支付、生产钱包接入、真实履约和灰度切换均不在本轮实现范围内，另行审批。

## 低成本实现策略（以核查结果为准）

R0 已完成代码、配置与运行库只读核查；本次没有修改运行库。确认的复用点与处理方式：

- Node/Express 主服务、现有后台登录与鉴权代码仍在；优先在同一服务增加独立业务路由，不另建 API 服务、容器或登录体系。
- `public/admin.html` 是现有 KC 技术后台页面。只复用视觉样式或通用组件，不改它的菜单和现有功能；新业务控制台用单独入口、单独的业务菜单。
- `web/` 下已有 Next.js 用户页面框架，但现有 API 封装代理到 Xboard。先保留页面和布局，只为已确认的代充路径新增业务 API 适配；逐页迁移，不整体重写前台。
- `tools/xboard-patches/KcIntegration/` 有部分代充插件、流水、售后和风险控制的参考代码。仅做逐项代码审查后择取可复用逻辑，不直接假设已部署、不复制整个插件，也不依赖 Xboard 菜单才能运行。
- 业务数据使用同一 MySQL 服务中的独立 `kc_business` 业务库；只读确认它与 `plus_papay`、`xboard` 分离，并核对 `0001`、`0002` 迁移校验值。当前实现适配现存表结构，拒绝自动建表/迁移；不得直接写 KC/Xboard 旧业务表。
- 本轮不做历史测试数据兼容或迁移；不在运行库造模拟数据。接口的写入行为仅在管理员实际调用 Mock 操作时发生；本轮验证没有调用任何写接口。

因此最小架构为：**一个现有 Node 服务 + 独立业务路由/存储 + 一个独立业务后台页面 + 逐步适配现有 Next.js 页面**。KC 后台保持原样；Xboard 现有壳层已包含非业务菜单隐藏规则和旧“代充运营”入口。本轮未改 Xboard 文件；旧入口尚未跳转至新后台，须配置运营可访问地址和登录衔接后再验收。

## 暂不纳入本期

- KC 后台菜单改造或迁移：不做，保持现状。
- Xboard 机场相关无关功能：不迁移到独立业务后台；允许本期收起其菜单入口，但不删除原功能、数据和路由。
- 分销、分销提现与推广看板：暂不开发。
- 发票：不做；交易凭证不等于发票。
- 优惠券/活动、在线客服：最低优先级，当前只保证不阻塞网站整体使用；在线客服后续可按人工接待体验补充方案。
- 启用 KC 自有代充能力、面向下游开放 API/独立站：仅作远期记录，不排入本期。
- 任何真实扣款、生产钱包收款、真实供应商履约：不做。

## 当前建议的下一步

R0–R2 的代码和只读验证已完成。继续交付前需要确认/配置 Xboard 菜单使用的 KC 浏览器访问地址与管理员登录方式，并获得 Docker 引擎可用环境；在这些条件具备前不部署、不写运行库。之后再按计划进入 R3 用户端增量接入。ZovoCard Mock、KC 后台菜单不改、Xboard 路由不删等约束持续有效。
