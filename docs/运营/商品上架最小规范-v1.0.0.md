# 商品上架最小规范（运营一页纸）

> 配套产出：《后台形态选型：自建 vs 改 Xboard》（`SP-2026-10-10`，已确认）③。
> 适用：在 Xboard 后台维护代充商品时的最小检查集（上架 / 改价 / 下架前对照使用）。
> 日期：2026-10-11　基线：`v1.13.0`　状态：现行

## 一、上架前（必查 6 项）

1. **商品归属**：在「代充商品」列表内操作（运营壳 → 商品与订单 → 代充商品）。
2. **价格口径**：数据库以「分」存储；前台全站按 **$** 展示——不出现非美元符号 / 字样（货币守护会拦截）。
3. **周期键**：monthly / quarterly / onetime 三键为准；**不要在数据库里手工改 period**（历史错配点）。
4. **kc_* 标注**：kc_card / kc_is_topup / kc_topup_amount 等按商品类型启用——**当前由技术侧配置**，自建商品配置页（路线阶段 4）落地后移交运营。
5. **展示与排序**：上架开关用 show；改价 / 改序走后台原生「编辑 + 排序」（plan/update + plan/sort），不直接改库。
6. **卡片配置**：分类与卡片文案（card-config）按需调整；若开放「购买卡密」入口，核对 card_buy 四项配置（总开关 / 主文案 / 副文案 / 说明）。

## 二、上架后（必验 4 步）

1. **健康门槛**：KC 健康摘要在线（`/api/integration/health` 的 supplier_health）——否则商品会被判「暂不可售」。
2. **前台核查**：商品页卡片出现、$ 价格正确、按钮形态符合配置（立即办理 / 购买卡密）。
3. **试单回路**：下单 → 收银台可达（不必真付）→ 订单列表可见该单。
4. **生效确认**：文案 / 开关类改动以「刷新后」为准（card_buy 保存即生效；其余走既有发布流程）。

## 三、红线（3 条）

- 不直接改数据库；一切经后台界面或契约接口。
- 金额一律美元展示；非美元符号 / 字样会被提交钩子（check-currency）拦下。
- 改价 / 下架前想清楚存量订单与收银台一致性；大改动前先备份配置（card-config 支持 reset 兜底）。
