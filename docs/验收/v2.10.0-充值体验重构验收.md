## 一、体验目标与解法（UX 视角）

| 用户痛点（原始状态） | 本次解法 |
|---|---|
| 客户**可能没用过 USDT**，不知道从哪下手 | 新增 **USDT 充值 3 步教程**（弹层样例）+ 充值弹层/钱包页双入口 |
| **选错区块链**资金可能到不了账，提示不醒目 | **独立网络警示区块**：必须选 **TRC20（波场 TRON）**，明确「选成 ERC20 / BEP20 → 资金无法找回」 |
| **倒计时不突出**，容易错过支付时限 | 倒计时**上提为独立高亮区块**（大号数字），剩余 ≤5 分钟自动进入**紧急脉冲态**并改文案「仅剩 MM:ss」 |
| **金额要带 4 位小数**但没有解释，用户容易手输错 | 精确金额**超大字 + 一键复制**，并加 **「为什么金额后面要带 4 位小数？」可展开解释**（尾数=唯一认单编号；少一位/多一分/取整都要转人工） |
| **转账不方便**（长地址手输易错） | **本地生成二维码可直接扫**（内容 `tron:{地址}`）+ 地址/单号**一键复制**；明确提示「扫码只带入地址，金额需手填」 |
| **关掉充值页就以为丢单** | **关页守卫**：关窗前弹「这笔充值还没支付完」（回显精确金额 + 剩余时间）→「继续支付」或「去待支付充值单」；**钱包页新增「待支付充值单」区块**可随时续付（逐秒剩余时间 + 继续支付） |
| 一屏堆信息、无流程感 | 重构为 **3 步引导**（① 选金额 → ② 扫码转账 → ③ 确认到账），步骤条随进度点亮 |

## 六、设计口径与取舍

1. **二维码内容只带地址**（`tron:{收款地址}`），**不带金额** —— 原因是各家钱包对 TRON URI `amount` 参数的支持不一致；带金额反而可能让用户转错金额。金额始终以「精确金额」区块为准（可一键复制）。
2. **二维码本地生成**（vendor 单文件库，非外链服务）—— 支付页不应依赖外部图床；离线/受限网络下仍可扫码。也刻意**不引入 npm 运行时依赖**（容器 `node_modules` 在镜像内，加依赖需重建镜像，本次不做）。
3. **关页不丢单**：关页守卫只对「pending 且未过期」的充值单生效；超时后不再拦截（此时订单已无支付价值）。
4. **精确金额与认单尾数口径未变**：尾数仅用于链上认单，不额外入账；教程与弹层文案均与既有口径一致。
5. **导航铁律遵守**：教程与「待支付充值单」都不进顶部导航（导航仍恒 5 项：代充 / 成品号 / 建站服务 / 权益包 / 我的订单）。
6. **待确认边界**：新手教程是**前端样例弹层**（够演示，非正式运营文档）；若需正式帮助中心（图文/视频/多语言）可另起独立页面。
