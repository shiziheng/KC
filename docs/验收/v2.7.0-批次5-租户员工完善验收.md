## 六、设计口径与已修正缺陷

1. **`kc_tenant_staff.role` ENUM 只有 `owner|staff`** —— 历史踩坑：写 `operator` 会触发 MySQL `Data truncated for column 'role'`；本批次端点**先校验角色值再写库**，非法值一律 400。
2. **自身守卫（本批次验收中发现并修正的缺陷）** —— 租户后台**没有**自助改密 UI，若 owner 重置自己的密码，会被批次 3 的强制首改闸门（写操作 403 `PASSWORD_CHANGE_REQUIRED`）锁死且无恢复路径。故在 `POST /:id/reset-password` 补 `SELF` 守卫（400），前端当前账号行的重置按钮置灰。首轮 UX 验收正是在此步暴露问题（点击自身行重置后再执行状态切换被 403 拒绝），修正后复验全绿。
3. **被禁用账号即时失效** —— `authenticateTenantStaff` 校验 `status='active'`，故禁用后**登录与已签发令牌同时失效**（401「账号已停用」）。
4. **内联 `onclick` 依赖全局名** —— `saveStaffRole` / `toggleStaffStatus` / `resetStaffPassword` 已在 IIFE 尾部 `window.xxx = xxx` 显式暴露（同类坑见 `buyPack`）。
