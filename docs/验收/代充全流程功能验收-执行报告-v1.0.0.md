## 六、本次执行中发现并处理的问题

### 1. 前台缺少可发现的「兑换卡密」入口（真实产品缺陷，已修复）
- **用户复检发现**：「整个网站前台没有看到卡密兑换的入口」。
- **现状核实（代码级）**：顶部导航恒 5 项（代充/成品号/建站服务/权益包/我的订单），页脚「帮助与支持 / 商品 / 关于 / 联系方式」各列均**无**兑换入口。点击路径仅 3 处：① 购买卡密弹层「完成」态的「去兑换」② 卡密订单详情的「去兑换」③ 直接代充订单的「继续开通」；其余只能靠 **`/redeem` 直链**或 **`?cdk=` 链接**进入。也即：**用户若没在本次购买流里，手上有一张卡密却无从站内导航找到兑换页**。
- **为什么首轮用例会「通过」**（这是本次最重要的教训）：E1/E2（匿名兑换）在 `_v2150` 中是**直接 `page.goto('/site?cdk=<卡密>')` 进入**的（见脚本 C2 段），E6 本身就是「`?cdk=` 直链」用例 —— 它们验证的是兑换**流程**是否正确，**从未断言「用户能否从前台发现入口」**；`_v2160` R1 断言只核对了「导航列表 = 5 项」+「`view-redeem` 元素存在」，同样不覆盖入口可发现性。**用例通过 ≠ 功能可发现。**
- **处理**：**按用户拍板将「兑换卡密」加入顶部导航**（定为第 6 项，`<button data-nav="redeem" onclick="goRedeem()">`），并同步 `go()` 在 `view==='redeem'` 时高亮该入口；**这意味着放宽原有「导航恒 5 项」铁律 → 导航现为 6 项**（代充/成品号/建站服务/权益包/我的订单/兑换卡密）。同步更新了断言该口径的脚本（`_v2150` E7/E7b、`_v290_frontend_ux_smoke` U1、`_v146_help_verify` F3）与文档（产品全景 / 本报告 / 用例）。
- **复跑证据**：`_v2150` 21 PASS / 0 FAIL（E7 命中 `nav=代充|成品号|建站服务|权益包|我的订单|兑换卡密`；E7b `{redeem:true,hasInput:true,active:true}`）。
- **口径修正**：原 E1~E6 仅覆盖「兑换功能」，本节新增 E7 覆盖「兑换入口可发现性」，二者不可互相替代。

### 2. `_v2130_product_e2e.js` F4 用例资产陈旧（非产品缺陷，已修复复跑）
- **现象**：首跑在 F4 处 `page.fill('#d-session')` 超时 30s 失败（脚本异常退出，exit 2）。
- **根因**：该脚本写于 v2.13.0，驱动的是 v2.15.0 之前的「裸露 Session textarea + 旧兑卡交付页」流程；前台在 v2.15.0 已改为 5 步呈递向导（`_v2150` A3 明确断言旧 textarea 已下线、`_v2170` B1 明确「下单后直接进第 5 步、不再跳旧兑卡页」），选择器 `#d-session` 已不存在。
- **处理**：将 F4 改造为走「详情页二选一 → 5 步向导（#wiz-sess-topup）→ 确认支付并开通」并在第 5 步验证建单；复跑 **10 PASS / 0 FAIL**，A1 的「后台建 → 前台可见 → 可买」端到端真实跑通。同一买入链路另有 `_v2170` F1、`_v2150` A7 独立佐证。
- **结论**：属测试脚本与前台 UI 漂移，**产品功能本身无缺陷**。

- **用户反馈**：①「钱包余额应该总是显示金额，目前有时候不显示余额」；②「订单管理应该加上一个刷新功能，因为有的订单状态变更了，但是页面没有同步」。
- **根因①**：顶栏 `#walletChip` 只在 `loadWallet()`（进入「钱包」页）时才写入金额，登录 / 首页时不刷新 → 恒显占位符 `—`。
- **根因②**：前台「我的订单」仅在**进入页面那一刻** `loadOrders()` 拉一次，停留期间订单状态变化（如 开通中 → 已完成）不会更新，且**无手动刷新入口**（后台各页已有刷新，前台缺）。
- **修复**（`public/site/index.html`）：①新增 `syncWalletChip()`（拉 `POST /api/tenant/wallet` 后写 `#walletChip`），在 `boot()`（登录态）与登录 / 注册成功后调用 → 顶栏「钱包余额」登录后即显金额；②「我的订单」面板头部加 **「刷新」按钮**（调 `loadOrders()`，加载中置灰为「刷新中…」）并显示 **「更新于 HH:MM:SS」**，让用户知晓数据新鲜度。
