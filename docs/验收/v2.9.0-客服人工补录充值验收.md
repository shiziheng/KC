## 一、业务背景（为什么需要）

顾客充值走链上 USDT（TRC20）收款，**平台扫链认单的依据是「精确金额的 4 位小数尾数」**（例如 `$200` 对应 `200.0084 USDT`）；客户若**不输小数**（转成整数 `200.0000`），扫链就匹配不到该笔订单 → 平台不会自动入账。

此时需要**客服去链上钱包人工核实**：确认该笔转账确实到账后，**手动把这笔金额补记到顾客账户余额**。

**此前缺口**：除「顾客自己在钱包页点『我已支付』」外，**没有任何服务端路径能写 `kc_customers.balance_cents`**（运营在后台只能查、不能补）；`kc_customer_wallet_ledger.type` 的 `adjust` 枚举长期无人写入。

## 二、交付面

| 层 | 内容 |
|---|---|
| 后端（`server.js`） | **`POST /api/admin/customers/:id/wallet/credit`**（`requirePermission('customer.write')`）：入参 `{ amount_cents\|amount, tx_hash(必填), recharge_no(可选), reason(可选) }` → 入账 + 写流水 + 可选把 `pending` 充值单置 `paid` + 落审计 |
| 前端（`public/admin.html`） | 顾客详情「账单」tab「充值单」标题行新增「**人工补录充值**」入口（仅 `customer.write` 角色渲染）+ 弹层 `#cust-credit-backdrop`（4 字段 + 红字风险提示 + 行内校验 + 二次确认）|
| 数据层 | **无新表**（复用 `kc_customer_wallet_ledger` / `kc_customer_recharges` / `kc_audit_logs`）|

### 端点契约

| 项 | 规则 |
|---|---|
| 权限 | `customer.write`（super / operator 具备；viewer / finance 无 → 403）|
| 必填 | `tx_hash`（链上交易哈希，人工补录必须留链上凭证）|
| 金额 | `amount_cents` 或 `amount`，须为 `$1 ~ $10000` 的**正数** |
| 幂等键 | **链上交易哈希**（`customer_id + ref=tx_hash` 查重）→ 重复即 **409 `DUPLICATE_TX`** |
| 流水 | **`type='adjust'`**、`ref=tx_hash`、`note='客服人工补录充值（充值单 rc_xxx）· 原因'`（**人工干预，与系统自动到账的 `recharge` 分开统计**）|
| 账单汇总 | `customerWalletData()` 汇总新增 **`adjust_total`**；后台账单卡由 4 张改为 **5 张**（充值合计 / **人工补录合计** / 消费合计 / 退款合计 / 当前余额）；流水类型标签 `adjust` → **「人工补录」**（后台 + 前台顾客钱包同步）|
| 关联单 | 提供 `recharge_no` 时，把该顾客该单的 `pending` 状态条件更新为 `paid` |
| 审计 | `customer.wallet_credit`，`before={balance_cents}`、`after={balance_cents, amount_cents, tx_hash, recharge_no, reason}` |
| 错误码 | 400 `TX_HASH_REQUIRED` / 400 `INVALID_AMOUNT` / 409 `DUPLICATE_TX` / 404 `NOT_FOUND` / 403 `FORBIDDEN` |

## 八、设计口径与边界

1. **幂等键 = 链上交易哈希**：同一笔链上转账**不可重复入账**（防客服重复点、防同一笔钱被记两次）。
2. **人工补录记为 `type='adjust'`（已按用户要求实施）**：**人工干预与系统自动到账分开统计** —— 账单「充值合计」只统计系统 `recharge`，人工补录单独进「**人工补录合计**」卡片与「人工补录」类型标签（后台 + 前台顾客钱包一致）；对账审计时两类可分别核对。`kc_customer_wallet_ledger.type` 的 `adjust` 枚举由此**首次被真正使用**（无需改表）。
3. **仅补「已真实到账」的钱**：弹层红字明确要求先到链上钱包核实；不做「未到账先垫付」。
4. **不做超上限/负数**：单次 `$1 ~ $10000`，正数入账（人工扣回另案，见 CHANGELOG「下一步」可选增强）。
