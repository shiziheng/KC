## 一、目标与范围

把主站前台的「模拟收款」（顾客自助点「我已支付」入账）升级为 **真实网关收款**：

1. **发起充值走网关下单** —— `POST /api/v1/order/create-transaction`，显式 `fiat=USD`；收款地址、应付金额、收银台地址一律以网关返回为准。
2. **到账由 `POST /api/wallet/bepusdt/notify` 服务端验签入账** —— 验签只证明来源可信，仍校验本地订单/金额/状态并幂等入账。
3. **生产模式关闭顾客自助入账** —— `POST /api/tenant/wallet/recharge/confirm` → 403，防顾客自刷余额。
4. **调度兜底对账** —— 定时 `POST /api/v1/pay/info` 查单，补入账 / 置过期，覆盖回调丢失。

**硬约束（验收同时校验）**：未配置 `BEPUSDT_API_URL` + `BEPUSDT_API_TOKEN` 时，行为必须与之前完全一致（仍是模拟收款），不得破坏现状；不得修改 KC 原生业务逻辑（卡池 / 代理池）。

## 五、真实网关联调（非桩，关键证据）

用 `bepusdt.js` 直连当前在跑的 BEpusdt（`:8080`，`usdt-trc20`，收款地址 `TSYdNdbx1Prw5jXjcWTgbY6N28BGmR1ufD`）：

- **签名被网关接受**：`POST /api/v1/order/create-transaction` 返 `status_code=200`，`data = {trade_id, order_id, token, actual_amount, payment_url, expiration_time:1199, status:1}`。
- **查单可用**：`POST /api/v1/pay/info {trade_id}` 返 `status_code=200` + `data.status / data.actual_amount`（1=待付 / 2=成功 / 3=过期）。
- **排查记录**：另有 `/api/v1/order/query`、`/api/v1/admin/orders`、`/api.php?act=order` 均 404 —— 网关**无公开订单查询接口**（v1 只有创建交易与收银台自用的 `pay/info`），故「调度兜底对账」采用 `pay/info`。
- **实测修正两处**：① `amount` 必须是 **JSON number**（传字符串 → Go `cannot unmarshal string ... type float64`）；② 必须显式 `fiat: 'USD'`（否则网关按 **CNY** 折算，$200 只收到约 29.9 USDT，即历史资损口径）。
- **清理**：联调探针订单已从网关台账删除。

## 八、结论与遗留

**结论**：功能 + UX 共 **18 条用例全绿**；真实网关签名/下单/查单联调通过；四套回归零回退；三门禁全绿。**未配置网关时行为与既有版本完全一致**（模拟模式），符合「不破坏现状」硬约束。

**遗留（待用户决策，非缺陷）**：

1. 是否把本地/生产环境切到真实 BEpusdt（填 `BEPUSDT_API_URL` + `BEPUSDT_API_TOKEN` + 可访问的 `KC_PUBLIC_BASE_URL`）——切换后顾客自助入账自动关闭，改由 notify + 调度对账入账。
2. 收款钱包为**非托管私人钱包**（只需公钥地址，无需私钥/企业钱包）——已与用户确认口径；运营注意该地址会公开出现在收银台/二维码中，建议专用地址并定期归集。
3. 收银台/回调域名现为内网地址（生产需切可访问域名）；BEpusdt 令牌需在收款前轮换。
