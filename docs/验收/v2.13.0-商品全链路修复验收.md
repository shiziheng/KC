## 一、用户反馈与根因

用户反馈三点：①「新增商品没有让选商品类型」（商品类型应为 代充/成品号/权益 等）；②「新增了以后前台也看不到新增的代充商品」；③「要做整个业务流程走查，而不是只看后台就完事了」。

**根因（两条，均已修复）**：

1. **商品类型缺失**：后台「新增商品」对话框**没有商品类型字段**；`POST /api/admin/products/save` 把卡片 `category` 写死 `recharge`，且**编辑分支根本不更新 `kc_type`** → 等于所有商品永远只能是代充。
2. **把「对外分销口径」当成了「商城上架门槛」**：前台目录的 SQL 过滤 + 可售判定要求 **`api_enabled=1` + 绑定白名单货源 + 上游成本>0**。运营勾了「在售 + 商城显示」的商品，只要没开「API 分销定价」就**在前台彻底看不到**（这就是用户看到的现象）；即使开了，货源成本为 0（`pro_5x`/`pro_20x`）也会被判「不可售（缺货）」。
3. **商城价无视运营售价**：价格只认「租户零售价 / 上游成本×(1+加价幅度)」，**后台「售价（美元）」填的数被忽略**，且不绑货源的商品售价恒为 0 → 直接不可售。

## 二、修复内容

| 面 | 改动 |
|---|---|
| 商品类型 | 新增/编辑对话框加「**商品类型** *」下拉（代充 `recharge` / 成品号 `account` / 建站服务 `website` / 权益 `entitlement`）→ 写 `kc_plans.kc_type` 并同步卡片 `card_json.category`；`kc_type` ENUM 扩容补 `website`（容错 ALTER）；`planTypeNorm()` 白名单同步；**编辑分支补齐此前完全未更新的 `kc_type`**；后台商品列表接口回吐 `kc_type` 供编辑预选 |
| 商城可见 | 目录与代理商商品接口过滤由 `api_enabled=1` 改为 **`show_flag=1 AND sell_flag=1 AND status='active'`**；`tenantSkuAvailable()` 改为「可见 + 在售 + active + 有价格」，**移除** `api_enabled / 货源白名单 / 成本>0` 三门槛（对外分销口径未动，仍走 `openApiSkuAvailable()`，`POST /api/open/v1/*` 语义不变）；paused 商品不再上前台 |
| 商城价 | 新增 `planListPriceCents()`；`tenantSkuPrice()` 优先级 = **租户零售价 → 运营售价（`prices_json`）→ 上游成本×(1+加价幅度)** |
| 前台分类 | 目录 `category` 以 `kc_plans.kc_type` 为准（`cardParse()` 归一卡片时会丢弃 `category`，原先一律回落 `recharge`，导致成品号商品落进代充 Tab） |
| 文案 | 对话框补「商城可见规则」说明；「API 分销定价」文案改为「仅影响对外分销接口，不影响商城上架」 |
