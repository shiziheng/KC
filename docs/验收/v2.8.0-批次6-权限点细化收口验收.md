### 端点权限映射（要点）

| 端点 | 权限点 |
|---|---|
| `billing` / `subscription` / `checkout` / `task-logs` | `order.read` |
| `runtime-logs` / `login-logs` | `audit.read` |
| `cdks` / `trigger-activation` | `entitlement.issue` |
| `cards` / `sessions` / `proxies` / `browser-pool` / `config` / `site-config` / `region` / `telegram` / `hcaptcha` / `gpt-api` / `integration` / `security/(2fa-mode\|paths)` | `system.config` |
| `addresses` | `admin.write` |
| `products` / `plans` / `listing-cards` / `upstreams` / `card-config`、`entitlements/grants\|rules\|prices` | **GET = 读点 / 非 GET = 写点**（如 `pricing.read` / `pricing.write`） |
| `tenants` / `api-clients` / `api-portal` | **GET = `tenant.read` / 非 GET = `tenant.write`** |

**刻意不设门**：登录壳与自助端点（`login` / `verify-secondary` / `secondary/session` / `session` / `change-password` / 2FA 自助）、共享读 `/api/admin/data`、`/api/admin/security/status`；已内联 `requirePermission` 的域（`customers` / `roles` / `admins` / `permissions` / `menus` / `audit-logs` / `password-resets`）不入表（避免双门）。

## 六、设计口径与已修正缺陷

1. **低权限角色启动刷 403（本批次验收中发现并修正的缺陷）** —— 批次 6 给既有端点加上权限门后，`bootAdmin` / `loadData`（**每 3 秒轮询**）仍**无条件**请求 `region` / `gpt-api` / `integration` / `cards` / `config` / `cdks` 等受控端点，`viewer`/`finance` 等角色登录即产生连串 **403 + 控制台报错**。修正：新增 `adminCan(point)` 助手，启动与轮询**按当前角色权限点跳过无权端点**；复验 `viewer` 启动 **403 = 0、业务 error = 0**。
2. **`finance` 缺 `menu.read` → 导航回落兜底菜单（本批次验收中发现并修正的缺陷）** —— 后台导航由 `GET /api/admin/menus` 驱动，该端点要求 `menu.read`；`finance` 内置角色**原不含**该权限 → 403 → 前端回落 `NAV_MENU_FALLBACK`。修正：`finance` 补 `menu.read`（种子 + 幂等对齐既有库行）。菜单管理页仍由 `admin.write` 把门，故 `finance` 仅获得"取导航"能力。
3. **`NAV_MENU_FALLBACK` 权限点过期（本批次验收中发现并修正的缺陷）** —— 该内置兜底为批次 4 旧值（多行 `permission: ''`），一旦菜单接口失败即按"人人可见"渲染，**会泄漏 `银行卡池` / `CDK 管理` / `Session 管理` / `代理池` / `浏览器池` 等无权页面**（实测 `finance` 兜底路径 22 项）。修正：兜底权限点**同步为批次 6 口径**。
4. **「系统与安全」组门 = `admin.write`（有意收紧）** —— `viewer` 虽持有 `admin.read` / `role.read` / `audit.read`，仍**看不到**该整组（与批次 4 退出条件 TC-F-11 一致）。属**有意设计**，非缺陷；如需放开可调整 `g_security` 行的 `permission`。
5. **`system.config` 复用为基础设施页统一权限点** —— 系统配置 / 卡池 / Session / 代理池 / 浏览器池 / 集成 / 站点定价 等共用 `system.config`，本批次**未再细分**（避免权限点爆炸）。属**语义取舍**，登记为待用户确认边界。
6. **不设门的理由** —— `/api/admin/data` 为「共享读」（登录壳与概览中心依赖）；`security/status` 供登录页与 2FA 自助判断；登录 / 改密 / 会话等壳端点必须放行。
