## 四、结论与遗留

- **本批次退出条件 TC-F-11 达成**：`viewer` 登录后导航完全不含「系统与安全」整组（HTTP 断言 + 浏览器实测双证）。
- 设计口径备忘：
  1. 菜单项 `key` **即页面 id**，与 `switchPage` 分派和页面容器一一绑定 → 全部容器 id 与分派逻辑本次未改，只换导航数据源；
  2. 组行 `permission` 语义为**整组访问门**（子项 permission 为空 = 不限制）——「系统与安全」以 `admin.write` 作门，故只读角色看不到整组；如需「按子项点粒度」显现，给子项补 permission 即可（组行留空）；
  3. 种子**幂等**（仅缺失时插入，已有行只补 `builtin=1`），**不改写运营已改过的显示名/排序**；`builtin=1` 项不可删（防页面失联），含子项的组需先删子项。
- **需用户确认的边界（非阻塞）**：本批次按已批准方案 §十 目标 IA **重排了技术后台导航分组**（新增「业务运营」「租户与客户」、代理池/浏览器池移入「自动化与任务」、系统配置/免税地址/登录日志移入「系统与安全」、账单记录更名「开通账单」），与产品红线「**KC 后台菜单不动**（业务需求不能修改技术后台结构）」的表述存在张力 —— 本批次属**平台管理工具**改造（非业务需求），故按计划执行；如需回退，改 `kc_admin_menus` 行的 `group_key` / `sort` 即可复位，无需改代码。
- 测试数据已清理：临时 viewer 管理员、临时菜单与相关审计噪声行已删除；核对 `kc_admin_users` = 1（super）、`kc_admin_roles` = 4（全内置）、`kc_admin_menus` = 32。
