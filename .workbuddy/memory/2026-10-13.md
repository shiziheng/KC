## 双模式定价与对外分销 API 补充设计（用户："客户固定价下单 + 未来 API 按上游价加价售卖，重点考虑"）

- **场景定性**：一套商品与货源数据 + **两个价格出口** + 一条共享履约链——①商城固定零售价（运营手设，不随成本波动）②API 报价=上游成本+加价规则（随成本浮动）。
- **文档**：`docs/方案/双模式定价与对外分销API设计-v1.0.0.md`（SP-2026-10-13-API-v1.0.0，《商品配置体验重构》补篇，已互相交叉引用）。
- **核心设计（已决策，无需用户选）**：
  1. 四层价格：成本价（上游同步/手填）→ 零售价（固定）→ 加价规则（比例/定额+保护价+取整）→ 报价（实时算）
  2. 商城固定价与 API 加价价**互不影响**（关键承诺）
  3. 对外 API：`/api/open/v1/*`（catalog/quote/orders/查单/回调，与内部 `/api/integration/*` 隔离）；鉴权 Key+HMAC 签名+时间戳+限流+幂等；**预充值余额**计费（不做后付）
  4. **锁价机制**：quote_id 60s + 成本变动 3% 容忍，超限 409 强制重报价（分销 API 关键工程点）
  5. API 订单走 **KC 自主履约**（不经 Xboard，复用 zovocard-client + 健康检查）
  6. 数据：kc_api_clients / kc_api_orders / kc_api_quote_logs + kc_plans 扩展（api_enabled/markup_type/markup_value/price_floor/rounding）+ upstream_price 启用
  7. 运营侧新增「API 客户管理」（发密钥/充值/限额/用量）
- **商品向导升级**：「②定价」双区——零售价（固定）+「API 分销定价」开关（加价方式/保护价/取整/报价模拟器）。
- **实施（并入原计划）**：UX-0→1→2 不变；**UX-4** 成本字段+模拟调价（0.5-1天）→ **UX-5** API MVP（2-3天）→ **UX-6** 客户管理+接入文档（1-2天）。上线护栏 5 条（mock 锁/限流审计/余额账本对账/全链路留痕/灰度）。
- **状态**：待批准；未动代码。
